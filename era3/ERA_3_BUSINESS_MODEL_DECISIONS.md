## 1. สรุปสั้น

เอกสารเดิม 4 ฉบับวางกลไกครบแล้ว แต่ยังขาด 3 อย่างที่ทำให้ลงมือเขียนโค้ดไม่ได้:

1. **ตัวเลขยุคเริ่มต้น** — ตัวอย่างเดิมเป็นสมาร์ตโฟน 28nm แต่เกมเริ่มที่ **ฟีเจอร์โฟน**
2. **มาตราส่วนของโลก** — ล็อตชิป 600 ชิ้นปนกับข่าวสั่งซื้อ 50,000 ชิ้น และบริษัทเล็กในแคมปัสทุน 1–3 แสนบาทปนกับโรงงานชิปหลายร้อยล้าน
3. **จุดขัดแย้งของสูตร** — มี 6 จุด (หัวข้อ 2) ที่ถ้าไม่แก้ AI คนละตัวจะเขียนโค้ดไม่ตรงกัน

เอกสารนี้ตัดสินใจให้ทั้งหมด และแยกชัดว่าอะไรคือ **ข้อเสนอ** อะไรคือ **ค่าที่ต้องปรับจูน**

| # | ปัญหา | อยู่ที่ไหน | การตัดสินใจ |
|---|---|---|---|
| 1 | **หน่วยพื้นที่ผิด** สูตร Yield ใช้ `dieAreaMm2 × D0` แต่ D0 มีหน่วยต่อ **cm²** | Blueprint ส่วน 5 | ใช้ `A_cm2 = dieAreaMm2 / 100` ก่อนเข้าสูตร Murphy เสมอ (ตรงกับ Mechanics 4.5) |

| 4 | **ลำดับคูณใน D0 กำกวม** เขียนบวกแล้วคูณต่อท้ายโดยไม่มีวงเล็บ | Mechanics 4.5 | `D0 = [D0_target + (D0_init − D0_target)·e^(−W/k)] × m_cleanroom × m_tool × m_team` |
| 5 | **ตัวเลขชิป/เวเฟอร์คนละชุด** ค่าเวเฟอร์ ฿150,000 vs ฿185,000, NRE ฿5M vs ฿4.5M, ต้นทุนชิป ฿315 vs ฿420 | Mechanics 5.1 vs Blueprint schema | ใช้ตารางในหัวข้อ 4 เป็นค่ากลางเดียว ส่วนตัวอย่างสมาร์ตโฟนเก็บไว้เป็นตัวอย่างยุคหลัง |

เรื่องที่ตรวจแล้ว **ถูกต้อง**: gross die, Murphy yield, ต้นทุนชิป ฿315, ตัวอย่างแบตและความร้อนทั้งชุด (15.4 ชม., 84%, 63%), กำไรต่อเครื่อง ฿1,938

หมายเหตุเล็กอีกสองข้อสำหรับตลาด (Mechanics 4.10): ค่าคุณลักษณะใน logit ต้อง **ทำให้เป็น 0–1 ก่อนคูณน้ำหนัก** และราคาใช้ `−α·ln(ราคา / ราคาอ้างอิงของกลุ่ม)` ไม่ใช่ ln ของราคาดิบ ไม่งั้นค่าเปลี่ยนตามสกุลเงิน

## 4. ตัวเลขยุคเริ่มต้น: ฟีเจอร์โฟน (Worked Example ครบห่วงโซ่)

### 4.1 ชิป baseband (บริษัทชิป)

- die 25 mm² (0.25 cm²), เวเฟอร์ 200 mm, 130 nm ที่นิ่งแล้ว D0 = 0.10 /cm²
- GrossDies = π·100²/25 − π·200/√50 = 1,256.6 − 88.9 ≈ **1,167**
- Yield = ((1 − e^(−0.025)) / 0.025)² = 0.9877² ≈ **97.6%** → GoodDies ≈ **1,138**

| รายการ | ฿/ชิป |
|---|---:|
| ค่าเวเฟอร์ ฿30,000 ÷ 1,138 | 26.4 |
| แพ็ก+ทดสอบ ฿12 ÷ yield แพ็ก 0.98 | 12.2 |
| royalty ให้ IP vendor | 4.0 |
| **ต้นทุนผันแปร** | **42.6** |
| NRE ฿2M ÷ 1M ชิ้น (ปันส่วนบัญชี ไม่หักเงินซ้ำ) | 2.0 |
| **ราคาขาย (A-bin)** | **70** |

กำไรส่วนเกินต่อชิป = 70 − 42.6 = **฿27.4**

### 4.2 แบรนด์มือถือ รุ่นฟีเจอร์โฟนมาตรฐาน

| ชิ้นส่วน | ฿ |
|---|---:|
| ชิป baseband 130 nm | 70 |
| PSRAM + NOR flash | 35 |
| จอสี CSTN 1.8" | 55 |
| แบต 3.7 V 1,000 mAh | 25 |
| PCB 4 ชั้น + PMIC + ปุ่มกด | 40 |
| RF 2G + เสาอากาศ | 30 |
| กล้อง VGA | 20 |
| ตัวถังพลาสติก | 25 |
| **BOM** | **300** |

- ขนส่ง+ภาษี 6% → 318; ค่าประกอบ EMS ฿25 → 343
- assembly yield 97% → 343 / 0.97 = **353.6**; + license RTOS ฿10 → **฿363.6** ต่อเครื่องดี
- ราคาปลีก ฿690, ร้านเอา 18% → **ขายเข้าร้าน ฿565.8**
- หักสำรองประกัน ฿8 และการตลาด ฿15 → **กำไรส่วนเกินต่อเครื่อง ≈ ฿179**
- R&D ฿8M ÷ คาดขาย 200,000 เครื่อง = ฿40 → **กำไรหลังปันส่วน R&D ≈ ฿139 (24.6% ของราคาขายเข้าร้าน)**
- **จุดคุ้มทุน R&D ≈ 44,600 เครื่อง**

**แบต:** 3.7 Wh × 0.92 = 3.40 Wh; ใช้งานเฉลี่ย 0.518 Wh/วัน (สแตนด์บาย 0.008 W × 23.5 ชม. + คุย 0.9 W × 0.3 ชม. + จอ/อื่นๆ 0.3 W × 0.2 ชม.) → **≈ 6.6 วัน**
**ความร้อน:** peak 0.9 W × R_th 5.0 = +4.5 °C ที่อากาศ 30 °C → 34.5 °C ต่ำกว่า 43 °C จึงไม่มีการลดความเร็ว ทำให้ฟีเจอร์โฟนไม่ต้องกังวลเรื่องความร้อน (ตรงกับธรรมชาติของมัน)

### 4.3 โรงงานรับจ้างผลิตเวเฟอร์ (Foundry)

| ค่า | ตัวเลข |
|---|---:|
| กำลังผลิต | 1,500 แผ่น/เดือน |
| ต้นทุนคงที่ (ค่าเสื่อม+คน+บำรุง) | ฿21M/เดือน |
| ราคาต่อแผ่น / ต้นทุนผันแปร | ฿30,000 / ฿9,000 |
| กำไรส่วนเกินต่อแผ่น | ฿21,000 |
| **จุดคุ้มทุน** | **1,000 แผ่น = 66.7% ของกำลังผลิต** |

ความต้องการตลาด: 1.17M เครื่อง/เดือน ÷ 0.98 ÷ 1,138 ≈ **1,047 แผ่น → utilization ≈ 70%** → กำไรเดือนละราว ฿1M (บางมาก) และตัวคูณคิว = 1/(1−0.70) ≈ 3.3 (ต่ำกว่าเพดาน 4)

**ผลที่ตามมาเองโดยไม่ต้องเขียนสคริปต์:** foundry ต้องแย่งลูกค้าและยอมลดราคาเพื่อให้พ้น 66.7% ถ้าตลาดหดหรือชิปที่ใช้เวเฟอร์น้อยกว่าเดิม (die เล็กลง) foundry ขาดทุนทันที

### 4.4 บริษัทชิปแบบ fabless และ IP vendor

- **fabless:** ต้นทุนคงที่ ≈ ฿82M/ปี (วิศวกร 60 คน × ฿100k × 12 + EDA ฿10M) ÷ กำไรส่วนเกิน ฿27.4/ชิป ⇒ **ต้องขายอย่างน้อย ≈ 3.0M ชิป/ปี หรือ ≈ 21% ของตลาด** ถึงจะคุ้ม
  → ถ้ามี 2 รายแบ่งตลาดคนละครึ่งอยู่ได้ แต่ถ้าแบรนด์ย้ายไปใช้ชิปอีกค่ายหมด ค่ายที่เสียลูกค้าเสี่ยงเจ๊งจริง
- **IP vendor:** royalty ฿4 × 14M = ฿56M/ปี เทียบต้นทุนคงที่ ≈ ฿36M (วิศวกร 30 คน) ⇒ อยู่ได้ แต่ขึ้นกับว่าชิปขายได้มากแค่ไหน

### 4.5 ทางเข้าของผู้เล่นรายเล็ก (ข้อค้นพบสำคัญ)

ถ้าบริษัทเล็กใช้ reference design + EMS รับจ้าง: ต้นทุนต่อเครื่องสูงกว่า ≈ ฿30 (ราคาชิ้นส่วนแพงกว่าเพราะ MOQ ต่ำ) → กำไรส่วนเกิน ≈ ฿149/เครื่อง

| รายการ | ฿ |
|---|---:|
| R&D (ใช้ reference design) | 2.4M |
| ล็อตแรก 5,000 เครื่อง × ฿394 | ≈ 2.0M |
| สำรองหมุนเวียน 3 เดือน | ≈ 1.0M |
| **ทุนขั้นต่ำ** | **≈ ฿5–6M** |
| จุดคุ้มทุน R&D | ≈ 16,100 เครื่อง |

เทียบกับ SME origin เดิมของเกมที่ทุน ฿100k–280k จึงต่างกัน **ราว 20–50 เท่า**

**การตัดสินใจ:** **ไม่เพิ่ม "phone origin" ใน v3.0.0** แต่ให้บริษัทเล็กเข้าสู่ธุรกิจมือถือเป็น **เส้นทางเติบโตภายหลัง** เมื่อสะสมทุนและความรู้ได้เอง ส่วนทางเข้า ฿150k ที่ทำได้จริงคือธุรกิจ **ซ่อม / ขายต่อเครื่องมือสอง / ขายอุปกรณ์เสริม** (ต่อยอดจาก origin `repair_service` ที่มีอยู่) ซึ่งยังเป็นส่วนหนึ่งของระบบนิเวศมือถือ

| P4 | **แยกผลทดสอบเป็น 2 ชั้น** "ผลที่บริษัทประกาศ" กับ "ผลวัดจริง" แล้วคะแนนรีวิวอิงส่วนต่าง | ได้ข่าวดราม่าแบบสมจริง (โบรชัวร์อวดเกินจริง → รีวิวแย่) |
| P5 | **ฟีเจอร์โฟนต้องไม่ถูกบังคับให้ตาย** `basic_voice` และ `durable_battery` คงมีผู้ซื้อหลังสมาร์ตโฟนเกิด เพราะน้ำหนักราคา/แบต/ความทนต่างกัน (ตามตารางกลุ่มลูกค้า) | ป้องกันสคริปต์ปลอมที่ฆ่าสินค้าเก่า |
| P6 | **ชุดทดสอบ "เหตุขัดข้อง"** ไฟดับโรงงาน, yield ตก, วิศวกรหลักลาออก, ราคา DRAM ผันผวน, ภาษีนำเข้าเปลี่ยน — แต่ละอย่างต้องมีผลลูกโซ่ที่อธิบายได้ | พิสูจน์ว่ามี emergence จริง |
| P7 | **ทุกโมดูลต้องมี audit ที่คืน `[]`** ตามที่เอกสารเดิมกำหนด และเพิ่ม **`scaleAudit`** ตรวจว่าหน่วยล็อตของบริษัทภายนอกกับรายชิ้นของแคมปัสแปลงกันลงตัว | แก้ปัญหา "ล็อต 600 ปนข่าว 50,000" ถาวร |

## 7. ลำดับงานที่แนะนำ (ปรับจากเฟสเดิม)

1. **แก้จุดขัดแย้ง 6 ข้อ** ในเอกสารเดิม (หัวข้อ 2) แล้วใช้ตารางหัวข้อ 4 เป็นข้อมูลตั้งต้นเดียว
2. **ชิ้นบาง (thin slice):** ฟีเจอร์โฟน 130 nm → foundry → แบรนด์ 4 ราย → ตลาด 14M/ปี → ปล่อยโลกเดิน 180 วันเกมโดยไม่แตะ ตรวจ 4 เกณฑ์เดิมของ Mechanics ข้อ 9 และ **อย่างน้อย 1 บริษัทเข้าใกล้ล้มละลายโดยไม่ใช่เพราะสคริปต์**
3. **ชิปรุ่นใหม่ + ES + ดีล + ข่าว** (Blueprint เฟส 3.1)
4. **แบรนด์ตอบสนอง + ความเข้ากันได้ + ความร้อน** (เฟส 3.2)
5. **คนนอกแคมปัสและการดึงตัว** (เฟส 3.3)
6. **UI สังเกตการณ์ + Edit Hub + ชุดทดสอบ** (เฟส 3.4)

## 8. สิ่งที่ยังไม่ได้ทำ / ยังไม่แน่ใจ

- ยังไม่ได้รันซิมหรือเทสต์ใดๆ การคำนวณทั้งหมดในเอกสารนี้เป็นการตรวจด้วยมือ
- ค่า D0, ราคาเวเฟอร์, ต้นทุนคงที่และอัตราส่วนต่างร้านเป็นค่าเกม ต้องปรับจูนจากหลายเซฟ
- ยังไม่ได้ตัดสินใจเรื่องปฏิทินยุค (ปีสมมติหรือปีจริง) และอัตราเติบโตของตลาดรายปี
- ความสัมพันธ์กับสินค้าเดิม 42 รายการ (เช่น ไมโครชิปแบบเก่าใน `data.js`) ยังต้องตรวจก่อนไม่ให้เกิดทางลัดฟรี
- ตัวเลขผู้ใช้/ตลาดไม่ได้อ้างอิงข้อมูลจริงของอุตสาหกรรม ใช้เป็นสัดส่วนเพื่อให้ระบบสมเหตุสมผลเท่านั้น
