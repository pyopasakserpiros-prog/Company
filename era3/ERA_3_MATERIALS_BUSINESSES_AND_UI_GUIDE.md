# Era 3 — แนวทางลงมือทำ: วัตถุดิบ ธุรกิจที่ต้องเพิ่ม สายประกอบ และ UI

- **สถานะ:** เอกสารออกแบบ (proposal) — ยังไม่ได้เขียนโค้ด runtime ยังเป็น v2.9.0
- **ใช้คู่กับ:** `ERA_3_BUSINESS_MODEL_DECISIONS.md` (ตัวเลข/มาตราส่วน), `ERA_3_FEATURE_AND_SMART_PHONES.md` (ข้อกำหนดเจ้าของ), `ERA_3_BUSINESS_MECHANICS_AND_CALCULATIONS.md`
- **ยังไม่ได้ตรวจซอร์สจริง** เอกสารนี้ไม่ได้เปิด `data.js` ดูรายการวัตถุดิบ 64 ชนิดเดิม ขั้นแรกของการลงมือคือ audit ว่าอะไรใช้ซ้ำได้
- **ปริมาณวัตถุดิบต่อชิ้นยังไม่ล็อก** เอกสารเจ้าของกำหนดให้วิจัยเคมี/กระบวนการก่อนใส่ตัวเลข ตารางด้านล่างกำหนดเฉพาะ "มีอะไร มาจากไหน ไปไหน"
- **กฎที่ไม่เปลี่ยน:** NPC ตัดสินใจทุกอย่างเอง UI เป็นการสังเกตการณ์เท่านั้น ไม่มีปุ่มสั่งงานบริหาร

## 1. หลักการจัดวัตถุดิบ (ตัดสินใจ)

1. **แบ่งเป็น 5 ชั้น** ของที่อยู่ชั้นสูงกว่าต้องมีทางผลิตหรือซื้อจากชั้นต่ำกว่าเสมอ ห้ามมีของงอกเอง
2. **เฉพาะของที่ "เกิดผลจริง" ถึงจะเป็นสต็อกแยก** ถ้าขาดแคลน คุณภาพ แทนกันไม่ได้ หรือมีวัฏจักรราคา จึงแยก ส่วนของจุกจิก (ตัวต้านทาน ขั้วต่อ) รวมเป็น "ชุด" (kit)
3. **ระดับความละเอียดต่างกันตามชั้น** เพื่อไม่ให้จำนวนบริษัทบวม:

| ชั้น | ใครทำ | ความละเอียด |
|---|---|---|
| T0 ทรัพยากรธรรมชาติ | เหมือง/บ่อ/ฟาร์ม | ใช้ระบบ extraction และบริษัทภายนอกเดิม (finite stock) |
| T1 วัสดุแปรรูป | "ผู้ผลิตวัสดุ" แบบรวม | บริษัทรวมที่มีสต็อกและกำลังผลิตจำกัด ราคาตามต้นทุน+ความขาดแคลน ไม่ต้องมีวิศวกรเป็นรายคน |
| T2 ชิ้นส่วนกึ่งสำเร็จ | บริษัทมีชื่อ | มีคน เครื่อง สัญญา |
| T3 ชิ้นส่วนสำเร็จ | บริษัทมีชื่อ | ตามเอกสารเดิม (SoC, จอ, แบต ฯลฯ) |
| T4 ผลิตภัณฑ์ | แบรนด์/EMS | มีด่าน EVT/DVT/PVT |

4. **ของเดิมที่หยาบ** (`microchip`, `silicon_wafer`, `pcb`, `battery`) ห้ามเหลือเป็นทางลัดฟรี ให้ตรวจผู้ใช้ทั้งหมดในสินค้าเดิม 42 รายการ แล้วเปลี่ยนให้ซื้อ "ชิปควบคุมทั่วไป" จากบริษัทชิปจริง (ราคาตลาด) แทนสูตรเดิม
5. **ของที่ไม่ใช่วัตถุดิบ:** ไฟฟ้า (kWh), น้ำบริสุทธิ์ (ลบ.ม.), บำบัดของเสีย เป็น **สาธารณูปโภคของสถานที่** ไม่ใช่สต็อกซื้อขายทั่วไป แต่ขาดไม่ได้ เพราะ fab ปิดได้จริงเมื่อไฟ/น้ำขัดข้อง

## 2. รายการวัตถุดิบและชิ้นส่วนที่เสนอ (thin slice: ฟีเจอร์โฟน)

รวมประมาณ **52 ชนิด** (9 + 16 + 15 + 9 + 3) ถ้าใน `data.js` มีของที่ซ้ำ เช่น ทองแดง พลาสติก แก้ว ซิลิกา ให้ใช้ของเดิม ไม่สร้างซ้ำ

### T0 ทรัพยากรธรรมชาติ (9)
`silica_quartz`, `copper_ore`, `tin_ore`, `silver_ore`, `crude_oil` (ฐานพอลิเมอร์), `lithium_ore`, `cobalt_ore`, `graphite_ore`, `fluorspar` (ฐานกรดไฮโดรฟลูออริก)

### T1 วัสดุแปรรูป (16)

| ชนิด | มาจาก | ใช้ที่ |
|---|---|---|
| `metallurgical_silicon` | ซิลิกา + คาร์บอน + ไฟฟ้า | → polysilicon |
| `electronic_polysilicon` | ซิลิคอนเมทัลลูร์จิคัล + เคมี | → ingot |
| `copper_cathode` | แร่ทองแดง | → foil, ลวด |
| `tin_ingot`, `silver_powder` | แร่ | → solder |
| `solder_alloy` | tin + silver + copper | → solder paste |
| `plastic_resin` (ABS/PC) | น้ำมันดิบ | → ตัวถัง |
| `pcb_laminate` | epoxy + ใยแก้ว + ฟอยล์ทองแดง | → PCB |
| `lithium_carbonate` | แร่ลิเธียม | → แคโทด |
| `cathode_lco`, `anode_graphite` | ลิเธียม+โคบอลต์ / กราไฟต์ | → เซลล์แบต |
| `electrolyte_separator` (ชุด) | น้ำมัน/เคมี | → เซลล์แบต |
| `process_chemicals` (กรด/ตัวทำละลาย) | fluorspar + เคมีพื้นฐาน | fab, PCB |
| `photoresist` | น้ำมัน/เคมี | fab |
| `specialty_gases` | แยกอากาศ/เคมี | fab |
| `display_glass_lc` (กระจก+ผลึกเหลว) | ซิลิกา + เคมี | จอ |

### T2 ชิ้นส่วนกึ่งสำเร็จ (15)
`silicon_ingot`, `wafer_200mm_blank`, `photomask_set`, `copper_foil`, `bare_pcb`, `solder_paste`, `package_materials_kit` (leadframe+สารหล่อ+ลวดเชื่อม), `battery_cell`, `passives_kit`, `lcd_panel_cell`, `rf_filter_crystal_kit`, `acoustics_kit` (ลำโพง/ไมค์/ตัวสั่น), `keypad_set`, `connector_kit`, `enclosure_shell`

### T3 ชิ้นส่วนสำเร็จ (9)
`wafer_lot` (WIP: เวเฟอร์ที่มี die), `soc_baseband`, `memory_psram_nor`, `pmic_chip`, `display_module`, `battery_pack`, `rf_module`, `camera_module`, `pcba`

### T4 ผลิตภัณฑ์ (3)
`finished_phone`, `charger_cable`, `retail_package` (กล่อง+คู่มือ)

> **ห่วงโซ่ย้อนหลังของ BOM ฿300 ในเอกสารก่อนหน้า:** ชิป → wafer_lot ← wafer_200mm_blank ← silicon_ingot ← polysilicon ← silicon ← silica+ไฟฟ้า ส่วนแบต → battery_cell ← cathode/anode/electrolyte ← ลิเธียม/โคบอลต์/กราไฟต์ ทำให้ทุกบาทของ BOM ตามกลับไปถึงแหล่งธรรมชาติได้

### เพิ่มในยุคสมาร์ตโฟน (P1 ไม่ต้องทำใน thin slice)
`bauxite`/`aluminium`, `indium` (ITO ทัชสกรีน), `rare_earth` (แม่เหล็ก), `nickel`, `tantalum`, `gold`, wafer 300 mm, photomask ละเอียดขึ้น, `oled_organics`, `touch_sensor_film`, `cmos_sensor_wafer`, `lens_module`, `package_substrate_hd`, MLCC แยกชนิด, `nand_flash`/`dram_lpddr`

## 4. "ห้องประกอบ" — สายประกอบเครื่องมือถือ

ใช้ระบบเครื่องจักร (`plant.js`) เดิม: เครื่องมีความจุ สภาพ ความผิดพลาด การบำรุงรักษา และต้องมีคนที่มีวิชารองรับ

| สถานี | เครื่อง/อุปกรณ์ | ความจุที่เสนอ (ค่าเกม) | ความรู้ที่ใช้ |
|---|---|---|---|
| 1 พิมพ์ solder paste | stencil printer | ≥ SMT | SMT process |
| 2 วางชิ้นส่วน (SMT) | pick & place | 12,000 ชิ้น/ชม.; บอร์ดฟีเจอร์โฟน ≈150 ชิ้น → 80 บอร์ด/ชม. ตามทฤษฎี | SMT/ฮาร์ดแวร์ |
| 3 reflow | เตาอบ | ไหลตามสาย | process |
| 4 ตรวจ AOI | AOI | ไหลตามสาย; จับของเสีย → rework | QA |
| 5 โปรแกรมเฟิร์มแวร์ | สถานีแฟลช | ~60 วินาที/เครื่อง | firmware |
| 6 ประกอบจอ/แบต/ตัวถัง | แรงงาน+jig | ~3 นาที/เครื่อง (20 เครื่อง/คน/ชม.) | assembly |
| 7 คาลิเบรตและทดสอบ RF | ห้อง RF shield | ~45 วินาที/เครื่อง | RF |
| 8 ทดสอบการทำงาน/ตกกระแทก (สุ่ม) | functional + drop tester | สุ่มตามแผนคุณภาพ | QA/reliability |
| 9 บรรจุ | สถานีแพ็ก | ตามสาย | logistics |

**คอขวดจริงอยู่ที่ SMT:** 80 × OEE 0.7 = **56 บอร์ด/ชม.** → สองกะ 16 ชม. × 330 วัน ≈ **295,700 เครื่อง/ปี ต่อสาย** ตลาดโลก 14 ล้านเครื่อง/ปี จึงต้องใช้ราว **47–48 สาย** กระจายหลาย EMS และ ODM (ค่านี้ช่วยตรวจว่ากำลังการผลิตรวมของ EMS สมเหตุสมผล)

**ความหมายต่อผู้เล่นรายเล็ก:** จุดคุ้มทุน 16,100 เครื่อง/ปี ≈ 0.05 สาย จึงไม่ควรลงทุนสาย SMT เอง ต้องจ้าง EMS ตามที่เอกสารก่อนหน้าสรุปไว้ แต่ **ขั้นประกอบมือ/ทดสอบ/บรรจุ** (สถานี 6–9) ทำเองได้ด้วยทุนไม่กี่แสน เป็นทางเข้าแบบค่อยเป็นค่อยไป

ของที่ส่งให้ EMS ประกอบ **ยังเป็นกรรมสิทธิ์ของแบรนด์** (customer-owned WIP) ต้องมีทางแสดงในแท็บสัญญา

## 5. แนวทาง UI

### 5.1 หลักการ (ตัดสินใจ)

1. **สังเกตการณ์ล้วน** ไม่มีปุ่มสั่งซื้อ/อนุมัติ/ตั้งราคา ปุ่มที่มีได้มีแค่: เลื่อนดู กรอง ติดดาว (watchlist) เร่งเวลาถึงเหตุการณ์ถัดไป และ Edit Hub ที่ติดป้าย "ทดลอง" ชัดเจนและมีบันทึก
2. **เล่าเรื่องก่อน ตัวเลขทีหลัง** หน้าแรกของทุกหน้าจอคือ "การ์ดเหตุผล" ที่อ่านจบใน 10 วินาที แล้วค่อยแตะลงไปดูตัวเลข
3. **เจาะลึก 4 ชั้น:** ภาพรวมโลก → บริษัท → ผลิตภัณฑ์/ล็อต/สัญญา → ตัวเลขดิบและเหตุการณ์ต้นทาง
4. **ออกแบบสำหรับ Android Chrome จอแคบ (~380 px)** ตัวอักษร ≥ 14 px, พื้นที่แตะ ≥ 44 px, ไม่พึ่งสีอย่างเดียว (ใช้ไอคอน/ข้อความร่วม), ข้อความไทยเป็นหลัก ไม่ให้เห็น JSON หรือรหัสภายใน
5. **ไม่เปลี่ยนโลก:** ทุกหน้าจออ่าน snapshot ที่โคลนมา ไม่เลื่อนเวลา ไม่เรียก RNG ไม่เซ็นสัญญา ตามกฎ UI/simulation เดิม
6. **ไม่ส่งแท็บเปล่า:** ทุกชิ้นงานต้องมีหน้าจอจริงที่ผูกกับข้อมูลที่เกิดแล้ว ห้ามส่งแท็บว่างเพื่อพิสูจน์ว่า "มีระบบ"

### 5.2 โครงหลัก: หน้าต่าง "อุตสาหกรรมมือถือ" 5 แท็บ

| แท็บ | ตอบคำถามอะไร | ส่วนประกอบหลัก |
|---|---|---|
| 1 ภาพรวม | โลกตอนนี้เป็นยังไง ใครกำลังเด่น ใครกำลังเดือดร้อน | แผงสุขภาพโลก (utilization ของ foundry, ส่วนแบ่ง, บริษัทใกล้เจ๊ง), ข่าวสำคัญ 5 ข่าว |
| 2 บริษัท | บริษัทนี้ทำอะไร มีอะไร ติดอะไร | การ์ดบริษัท (เงินสด/อายุเงินสด, คนสำคัญ, โครงการ, สัญญา, เหตุผลล่าสุด) |
| 3 ผลิตภัณฑ์ | รุ่นนี้ประกอบจากอะไร ดีหรือไม่ | ต้นไม้ BOM + สถานะความเข้ากันได้, เกจแบต/ความร้อน, ผลทดสอบเทียบคำโฆษณา |
| 4 ห่วงโซ่/สายผลิต | ของมาจากไหน ติดตรงไหน | แผนภาพการไหล T0→T4, ล็อตเวเฟอร์ (gross→good→A/B/scrap), คิวเครื่อง, สถานะสถานีประกอบ |
| 5 ตลาด | ใครซื้อ ทำไม | กรวยตลาด sell-in → sell-through → installed base, กลุ่มลูกค้า, รีวิว |

เพิ่มปุ่มด้านบนเสมอ: **"ทำไมถึงเป็นแบบนี้?"** ซึ่งเปิดไทม์ไลน์เหตุ→ผลของข้อมูลที่กำลังดู (อ้าง `sourceEventId`)

### 5.4 ชิ้นส่วน UI ที่ต้องสร้าง (reusable)

### 5.5 ประสิทธิภาพและความถูกต้อง

- ข้อมูลอุตสาหกรรมอัปเดต **รายวัน (ปิดวัน)** ไม่ใช่ทุก tick; UI ต้องแสดงเวลาของข้อมูลล่าสุด
- แสดงรายการแบบแบ่งหน้า/เลื่อนโหลด จำกัดแถวต่อจอ ไม่เกิน ~150 รายการที่ใช้งานอยู่ ที่เหลือเข้า "ประวัติ"
- วาดเฉพาะแท็บที่เปิดอยู่ ปิดหน้าต่างแล้วไม่คำนวณ
- วัด benchmark แยก: เวลาปิดวันของอุตสาหกรรม กับเวลาวาดหน้าจอบนมือถือ ไม่เอามาปนกัน
- ทดสอบอัตโนมัติ: เปิดทุกแท็บแล้วตรวจว่าโลก (สถานะ/RNG/เวลา) ไม่เปลี่ยน; ตรวจเค้าโครงที่ 380 px ไม่มีแถบเลื่อนแนวนอน

## 6. ลำดับลงมือทำที่แนะนำ

1. **Audit ของเดิม:** เทียบรายการหัวข้อ 2 กับ `data.js` เดิม 64 ชนิดและ 40 สูตร ทำตาราง "ใช้ซ้ำ / เพิ่มใหม่ / ต้องแก้" พร้อมรายชื่อสินค้าเดิมที่ใช้ `microchip`/`wafer`/`pcb`/`battery`
2. **ชุดข้อมูลวัตถุดิบ + สูตร (T0–T3)** พร้อมชุดทดสอบ **การอนุรักษ์** (ของไม่งอก เงินสมดุล ล็อตลงตัว) และ audit ที่คืน `[]`
3. **บริษัทต้นน้ำ + utilities** ตามตารางหัวข้อ 3 (P0) พร้อม UI แท็บสายผลิต แบบอ่านอย่างเดียว
4. **สายประกอบ (หัวข้อ 4)** ผูกกับ `plant.js` และ EMS; UI สถานะสถานี
5. **แท็บผลิตภัณฑ์ + ตลาด + การ์ดเหตุผล** เมื่อมีรุ่นแรกที่ผลิตและขายจริงแล้ว
6. **แผงสุขภาพโลก** และทดสอบ "ปล่อยโลกเดิน 180 วัน โดยไม่แตะ" ตามเกณฑ์ thin slice
7. ค่อยเพิ่มของชั้น P1 (สมาร์ตโฟน) เมื่อฟีเจอร์โฟนครบวงจรและ audit ผ่าน

แต่ละขั้นต้องส่ง **ทั้งข้อมูล ตรรกะ และหน้าจอที่ดูได้จริงพร้อมกัน** ตามที่เจ้าของโปรเจกต์ต้องการให้ตรวจสอบได้ทีละชิ้น

## 7. ข้อที่ยังไม่แน่ใจ

- ยังไม่ได้ดูซอร์สจริง จึงยังไม่ทราบว่าวัตถุดิบเดิมชนิดใดใช้ซ้ำได้ และสินค้าเดิมกี่รายการต้องแก้
- ปริมาณวัตถุดิบต่อชิ้นและเวลาผลิตในแต่ละสถานี (ยกเว้นตัวอย่างสายประกอบ) ยังไม่ได้วิจัยและยังไม่ล็อก
- จำนวนบริษัทที่ซิมรับไหวต้องวัดจริงก่อนตัดสินใจแยกบริษัทรวมออกเป็นรายตัว
- เค้าโครง UI เป็นข้อเสนอเริ่มต้น ควรลองกับจอมือถือจริงและแก้ตามการใช้งาน
- ตัวเลขทั้งหมดเป็นค่าเกม ไม่ได้ยืนยันกับข้อมูลโลกจริง
