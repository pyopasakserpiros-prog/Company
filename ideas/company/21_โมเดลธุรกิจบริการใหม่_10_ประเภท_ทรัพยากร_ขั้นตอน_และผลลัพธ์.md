# โมเดลธุรกิจบริการเพิ่มเติม 10 ประเภท: สิ่งที่ต้องมี ทรัพยากร ขั้นตอน และผลลัพธ์

> สถานะ: **ข้อเสนอสำหรับอนาคต ยังไม่ได้พัฒนาในเกม**
>
> วันที่: 11 พฤศจิกายน 2026 · ฐานซอร์สที่ตรวจ: `main` commit `934a489`
>
> รายงานนี้ใช้คู่กับบท 19 (กองรถขนส่ง) และบท 20 (ซอฟต์แวร์/แอป) รวมเป็นชุด 12 โมเดลธุรกิจ ID กลไกและโครงสร้างใหม่เป็นข้อเสนอ ต้องตรวจ registry ปัจจุบันก่อนเพิ่มจริง

## 1. ขอบเขตและความสัมพันธ์กับคลังเดิม

บท 11/12 มีอุตสาหกรรมการผลิต กิจการเริ่มต้น บริการบัญชี ติดตั้ง และโลจิสติกส์อยู่แล้ว รายงานนี้เพิ่มรูปแบบการขาย **กำลังให้บริการ ทรัพย์สินให้เช่า ผลตรวจ หรือผลลัพธ์ตามสัญญา** บางธุรกิจต่อยอดสินทรัพย์/ทักษะเดิมอย่างชัดเจน เช่น การดูแลเครื่องจักรภายในขยายเป็นรับงานภายนอก และโซลาร์ใช้เองขยายเป็นบริการพลังงาน จึงไม่อ้างว่าแนวคิดพื้นฐานทั้งหมดไม่เคยปรากฏมาก่อน

NPC/CEO เป็นผู้เลือกลงทุน รับสัญญา และดำเนินงาน ผู้เล่นเฝ้าดู ห้ามเพิ่มงานกดประจำให้ผู้เล่น Human Core และ hash เดิมคงไว้ทั้งหมด ทักษะ สถานี และสถานะธุรกิจเพิ่มภายนอกแกน

## 2. โครงสร้างธุรกิจร่วมที่ควรเพิ่ม

| องค์ประกอบเสนอ | หน้าที่ |
| :--- | :--- |
| `businessUnit` | สายกิจการ งบ ผู้รับผิดชอบ คน/ทรัพย์สินที่จัดสรร และผลดำเนินงาน |
| `serviceContract` | คู่ค้า ขอบเขตงาน หน่วยขาย เงื่อนไขรับมอบ รอบบิล เงินมัดจำ และข้อพิพาท |
| `serviceJob` | input, output, dependency, คน สถานี เวลาจอง และหลักฐานงานสำเร็จ |
| `assetInstance` | เจ้าของ สภาพ อายุ ตำแหน่ง สถานะเช่า/ซ่อม และต้นทุน |
| `resourceReservation` | จองทรัพยากรร่วม ป้องกันใช้คน รถ พื้นที่ หรือเครื่องเดียวกันพร้อมกัน |
| `custodyRecord` | ของที่ลูกค้าฝากหรืออุปกรณ์ที่ส่งให้ยืม แยกจากสินค้าขายของบริษัท |
| `acceptanceRecord` | ผลตรวจ ผู้รับมอบ เวลา และ contract/job ID ที่เก็บเงินได้ |
| `billingSchedule` | งวดที่ถึงกำหนด รายได้ที่รับรู้ ลูกหนี้ และยอดจ่ายจริง ไม่ใช่รายได้ฟรีทุก tick |

**วงจรมาตรฐาน:** ความต้องการจริง → เสนอราคา → ตรวจคน/เครื่อง/เงิน → ยืนยันสัญญา → จอง → ทำงาน → ตรวจรับ → ส่งมอบ → ออกบิล → เก็บเงิน → ดูแล/ต่ออายุ/ยุติ

ชื่อ field ทั้งหมดด้านบนยังเป็นข้อเสนอ ไม่ใช่ API ที่ยืนยันว่ามีอยู่แล้ว `data.js` เหมาะกับ registry; `sim.js` กับคิว/การตัดสินใจ; `economy.js` กับรายการเงิน; `save.js` กับ validation; `api.js`/UI กับเหตุผลและผลลัพธ์

## 3. บริษัทเช่าเครื่องมือและเครื่องจักร

**ขายอะไร:** ให้เช่าเครื่องปั่นไฟ รถยก เครื่องเชื่อม หรืออุปกรณ์ก่อสร้างเป็นวัน/ชั่วโมง ลูกค้าโรงงานและผู้รับเหมาซื้อการใช้ asset ไม่ได้ซื้อกรรมสิทธิ์

**สิ่งที่ต้องมี:** ลานเก็บ/ซ่อม ช่างตรวจสภาพ ธุรการสัญญา ฝ่ายขาย และขนส่งของตนเองหรือจ้างบท 19 เริ่มเครื่องมือหนึ่งประเภทก่อน ไม่ต้องมีกองเครื่องครบทุกชนิด

**ทรัพยากร/กลไกเพิ่ม:** `rental_asset` เป็น asset รายชิ้น; `rental_hour` เป็น capacity; `repair_part`, `lubricant`, `inspection_tag` เป็นของสิ้นเปลือง เพิ่มปฏิทินจอง ความเสียหาย การส่งคืนช้า และเงินประกัน

**ขั้นตอน:** ซื้อ/รับเครื่อง → ตรวจและบันทึกสภาพ → เสนอช่วงเช่า → ตรวจการจองและรับมัดจำ → ส่งพร้อมหลักฐาน → ให้เช่า → รับคืน/ตรวจ → คิดค่าจริงและคืนประกัน → ซ่อมหรือปล่อยเช่าต่อ

**ผลลัพธ์:** รายได้เช่า asset เสื่อมตามการใช้ ตารางงานอนาคต และภาระรับคืน เครื่องที่ยังอยู่นอกบริษัทใช้กับงานภายในไม่ได้

**ข้อแลกเปลี่ยน:** ซื้อแพงแล้วว่างงานเงินจม เครื่องเช่าราคาดีแต่เสี่ยงเสียหาย CEO เทียบ utilization หลายรอบกับค่าซ่อมและอายุที่เหลือ ไม่ซื้อเพราะการจองวันเดียว

**กฎเงิน/ตรวจรับ:** มัดจำเป็นเงินที่มีภาระคืน ไม่ใช่รายได้ทั้งหมด รับคืนซ้ำไม่คืนเงินซ้ำ ห้ามจองชนและห้ามคิดค่าเช่าต่อหลังคืนตามสัญญา

**เส้นทางโต:** เครื่องมือเล็ก → กลุ่มเครื่องจักรเฉพาะ → สัญญาโรงงานระยะยาว → เชื่อมขนส่งและทีมช่างภาคสนาม

## 4. ซักรีดอุตสาหกรรมและเช่าผ้าลินิน

**ขายอะไร:** ซักผ้าโรงแรม ชุดพนักงาน หรือเช่าชุดผ้าพร้อมรับคืน ไม่รวมงานปลอดเชื้อทางการแพทย์ในรุ่นแรก

**สิ่งที่ต้องมี:** โซนรับผ้าสกปรกแยกจากผ้าสะอาด เครื่องซัก/อบ/รีด ระบบน้ำและน้ำทิ้ง พนักงานประจำเครื่อง QC และรอบรถรับส่ง

**ทรัพยากร/กลไกเพิ่ม:** `detergent_kg`, `softener_liter`, `wash_water_m3`, `heat_kwh`, `laundry_bag` และ batch ที่แยกเจ้าของ ประเภทผ้า ระดับคราบ และจำนวนชิ้น; ผ้าเช่าเป็น asset pool ไม่ใช่ของลูกค้า

**ขั้นตอน:** รับและชั่ง/นับ → คัดประเภท → จองเครื่องตามน้ำหนัก → ซัก → อบ → รีด/พับ → QC ความสะอาด/จำนวน → ส่งคืน → ออกบิลตามน้ำหนักหรือจำนวนที่ตกลง

**ผลลัพธ์:** ผ้าสะอาดที่รับมอบ รายได้ต่อรอบ บัญชีผ้าสูญหาย/ชำรุด และสัญญาประจำ หาก QC ไม่ผ่านต้องซักซ้ำใช้ทรัพยากรจริง

**ข้อแลกเปลี่ยน:** รวม batch ลดต้นทุนแต่เพิ่มเวลารอ; สัญญาราคาถูกล็อตใหญ่กิน capacity จนอาจพลาดลูกค้ากำไรสูง

**กฎเงิน/ตรวจรับ:** สัญญาต้องเลือกว่าจะคิดตามกก.หรือชิ้น ไม่เรียกเก็บทั้งคู่โดยไม่ได้ตกลง จำนวนผ้ารับ = คืน + ค้างงาน + สูญหายที่มีหลักฐาน น้ำทิ้งต้องถูกจัดการ

**เส้นทางโต:** ซักชุดโรงงาน → ผ้าโรงแรม → ให้เช่าผ้าประจำ → สาขาพร้อมเครือข่ายรับส่ง

## 5. คัดแยกและรีไซเคิลของเสียอุตสาหกรรม

**ขายอะไร:** บริการรับวัสดุเหลือใช้/คัดแยก และขายวัตถุดิบทุติยภูมิให้โรงงาน เริ่มกระดาษ พลาสติก และโลหะที่ไม่อันตราย

**สิ่งที่ต้องมี:** ลานแยกประเภท เครื่องชั่ง คัด/อัดก้อน PPE ทีมงาน ตรวจสิ่งปนเปื้อน และผู้รับกำจัดส่วนที่ขายไม่ได้

**ทรัพยากร/กลไกเพิ่ม:** `scrap_paper_kg`, `scrap_plastic_kg`, `mixed_scrap_kg`, `baling_wire`, `process_water_m3`, `recovered_metal_kg`, `residue_kg`; แต่ละล็อตมีเจ้าของ ความบริสุทธิ์ และที่มา

**ขั้นตอน:** ตกลงว่าจะรับซื้อเศษหรือคิดค่ากำจัด → ตรวจ/ชั่งรับ → แยก → บด/อัด/ทำความสะอาดตามชนิด → ทดสอบเกรด → ขายของกู้คืน → ส่งส่วนตกค้างให้ผู้รับกำจัด → ปิดหลักฐาน

**ผลลัพธ์:** วัตถุดิบกู้คืนที่ใช้ผลิตได้เฉพาะเกรดที่ผ่าน รายได้ขายวัสดุ/บริการ และต้นทุนกากตกค้าง

**ข้อแลกเปลี่ยน:** ล็อตปนเปื้อนราคาถูกอาจใช้แรงงานสูงจนขาดทุน มูลค่าขายและอัตรากู้คืนเปลี่ยนได้จากคุณภาพจริง

**กฎเงิน/ตรวจรับ:** สมดุลมวลสาร `input = recovered + residue + measuredProcessLoss` ทุก loss มีเหตุผล ห้ามเศษเหล็ก 1 กก.แปลงเป็นโลหะ 2 กก. ค่ารับกำจัดกับค่าซื้อเศษเป็นคนละสัญญา ไม่เก็บทั้งคู่โดยอัตโนมัติ

**เส้นทางโต:** คัด/อัดก้อน → ล้างและแปรรูปเฉพาะวัสดุ → สัญญารับเศษจากโรงงาน → ส่งกลับผู้ผลิตเป็นวงจรปิด โดยไม่อ้างว่ารีไซเคิลได้ 100%

## 6. บริการน้ำอุตสาหกรรมและบำบัดน้ำเสีย

**ขายอะไร:** น้ำคุณภาพตามสเปก หรือบริการบำบัดน้ำเสียตามปริมาตร/ภาระมลพิษ เป็นการใช้ระบบ utility หารายได้จากภายนอก

**สิ่งที่ต้องมี:** ถังพัก ท่อ ปั๊ม ระบบกรอง/บำบัด ห้องทดสอบ ผู้ปฏิบัติการ ช่าง และงบดูแลคุณภาพ มีแผนหยุด/ลดรับเมื่อ capacity เต็ม

**ทรัพยากร/กลไกเพิ่ม:** `raw_water_m3`, `filter_media_kg`, `treatment_reagent_kg`, `membrane_module`, `pump_kwh`, `sludge_kg`; แยกอุปกรณ์ใช้ซ้ำ สารเคมีต่อ batch และตัวกลางกรองที่เปลี่ยนตามอายุ

**ขั้นตอน:** เก็บตัวอย่าง → วิเคราะห์ → เสนอเงื่อนไขรับเข้า → รับและพัก → บำบัด/กรอง → ทดสอบขาออก → ส่งน้ำที่ผ่านเกณฑ์หรือบำบัดซ้ำ → จัดการ sludge → ออกบิล

**ผลลัพธ์:** น้ำตามสเปกที่ใช้ได้จริง ผลตรวจแต่ละ batch ตะกอนที่ต้องกำจัด รายได้บริการ และภาระรักษา SLA

**ข้อแลกเปลี่ยน:** น้ำเข้าที่มีภาระสูงกิน capacity มากกว่าแม้ปริมาตรเท่ากัน กรองละเอียดเพิ่มต้นทุน/เวลาหรือสูญเสียน้ำบางส่วน

**กฎเงิน/ตรวจรับ:** น้ำไม่ผ่านห้ามขายเป็นเกรดสูง การนำกลับใช้ต้องมีสมดุลน้ำและของเสีย ไม่เสกน้ำใหม่หรือล้างค่ามลพิษทิ้งโดยไม่มีต้นทุน

**เส้นทางโต:** บริการ onsite ให้โรงงานเดียว → สัญญาหลายโรงงาน → น้ำหมุนเวียนในนิคม → บริการคุณภาพเฉพาะอุตสาหกรรม

## 7. ห้องปฏิบัติการสอบเทียบและทดสอบเครื่องมือ

**ขายอะไร:** รายงานสอบเทียบเครื่องชั่ง เซนเซอร์อุณหภูมิ หรือเครื่องมือวัด และทดสอบสินค้าตามวิธีที่ห้องแล็บทำได้จริง

**สิ่งที่ต้องมี:** ห้องควบคุมสภาพแวดล้อม เครื่องมาตรฐานอ้างอิง ผู้ทดสอบที่มีคุณสมบัติ ผู้ทบทวนผล และขอบเขตบริการที่อนุมัติในเกม

**ทรัพยากร/กลไกเพิ่ม:** `reference_standard_asset`, `reference_sample`, `test_reagent`, `calibration_label`, `lab_minute`; เพิ่มความไม่แน่นอนการวัด วันครบกำหนดของเครื่องอ้างอิง และ chain of custody

**ขั้นตอน:** รับเครื่อง/ตัวอย่าง → บันทึกสภาพและขอบเขต → ปรับสภาพ → วัดเทียบตามจุด → วิเคราะห์ความคลาดเคลื่อน → ทบทวน → ออกรายงาน → คืนเครื่อง/ตัวอย่างและเก็บเงิน

**ผลลัพธ์:** ค่าที่วัด ความไม่แน่นอน ข้อจำกัด และรายงานที่ตรวจย้อนกลับได้ **รายงานสอบเทียบไม่ใช่ใบผ่านคุณภาพอัตโนมัติ** เครื่องลูกค้าอาจไม่ผ่านเกณฑ์ตามการตีความที่ตกลง

**ข้อแลกเปลี่ยน:** เครื่องอ้างอิงราคาแพง/ต้องดูแล คิวเร่งด่วนอาจชนงานเดิม การทดสอบบางชนิดทำลายตัวอย่างและต้องขออนุญาตในสัญญา

**กฎเงิน/ตรวจรับ:** เครื่องอ้างอิงหมดอายุห้ามใช้ปล่อยผลใหม่ ผลที่ไม่ผ่านก็มีค่าบริการตามงานที่ทำจริง ไม่ขายใบรับรองโดยไม่ทำการตรวจ

**เส้นทางโต:** เครื่องชั่งหนึ่งช่วง → อุณหภูมิ → งาน onsite → ขอบเขตทดสอบเฉพาะทาง เชื่อม QC และห้องเย็นบท 19

## 8. ทีมซ่อมบำรุงโรงงานภาคสนาม

**ขายอะไร:** รับตรวจ/ซ่อมเครื่องจักรของบริษัทอื่น และสัญญาบำรุงตามรอบ ต่างจากการซ่อมเครื่องของตนที่มีในเกม/ไอเดียเดิม

**สิ่งที่ต้องมี:** รถบริการหรือจ้างขนส่ง ชุดเครื่องมือ อะไหล่ ทีมช่าง ผู้ประสานนัด และขั้นตอนตัดแหล่งพลังงานก่อนทำงาน

**ทรัพยากร/กลไกเพิ่ม:** `bearing`, `drive_belt`, `industrial_sensor`, `maintenance_lubricant`, `seal_kit`, `service_van_asset`; เครื่องมือใช้ซ้ำ ส่วนอะไหล่หักเมื่อเปลี่ยนจริง

**ขั้นตอน:** รับอาการ → ประเมิน/นัด → เดินทาง → ตรวจหน้างาน → เสนอวิธีและราคา → รออนุมัติ → ซ่อม → ทดลองเดินเครื่อง → ลูกค้ารับมอบ → ออกบิล/รับประกันเฉพาะงาน

**ผลลัพธ์:** เครื่องลูกค้ากลับมาใช้งานหรือรายงานว่ายังซ่อมไม่ได้ อะไหล่ที่ใช้ รายได้ตรวจ/ซ่อม และข้อผูกพันรับประกัน ไม่ต้องรับประกันว่าทุกงานซ่อมสำเร็จ

**ข้อแลกเปลี่ยน:** สัญญาเหมารายเดือนรายได้สม่ำเสมอแต่เหตุขัดข้องหนักอาจกินชั่วโมงทีม คิวฉุกเฉินต้องไม่ใช้ช่างคนเดียวกับงานที่จองอยู่แล้ว

**กฎเงิน/ตรวจรับ:** มีอะไหล่แต่ช่างยังไม่ทำงานเครื่องไม่หายเอง ค่าดูอาการแยกจากค่าซ่อมตามสัญญา เปลี่ยนอะไหล่ซ้ำไม่ได้รับเงินซ้ำโดยไร้งานจริง

**เส้นทางโต:** ช่างทั่วไป → สัญญาโรงงานประจำ → ชำนาญเครื่องเฉพาะ → ตรวจเชิงป้องกันตามข้อมูลสภาพเครื่อง

## 9. ศูนย์ฝึกอาชีพและพัฒนาทักษะสำหรับบริษัทภายนอก

**ขายอะไร:** ที่นั่งอบรมเชิงปฏิบัติและการประเมินผลให้บริษัทลูกค้า ต่อยอดศูนย์ฝึก/mentorship เดิมด้วยการขายบริการภายนอก

**สิ่งที่ต้องมี:** ห้องเรียน สถานีฝึก อุปกรณ์ความปลอดภัย ผู้สอนที่ชำนาญ ผู้ประเมิน และแผนหลักสูตรที่มี prerequisites

**ทรัพยากร/กลไกเพิ่ม:** `training_kit`, `practice_material`, `assessment_sheet`, `training_station_minute`; อุปกรณ์ฝึกใช้ซ้ำ วัสดุทดลองบางส่วนสิ้นเปลือง ที่นั่งและเวลาผู้สอนจำกัด

**ขั้นตอน:** สำรวจช่องว่างทักษะ → ทำหลักสูตร → รับสมัครที่มีคุณสมบัติ → จองผู้สอน/สถานี → สอนและฝึกจริง → ประเมิน → ออกผล → ติดตามหลังกลับไปทำงาน

**ผลลัพธ์:** รายได้ต่อที่นั่งหรือรุ่น คะแนน/ทักษะที่เพิ่มตามการเรียนรู้จริง และรายงานผล ผู้เข้าเรียนไม่จำเป็นต้องผ่านทุกคน ใบเข้าร่วมไม่เท่ากับใบยืนยันความชำนาญ

**ข้อแลกเปลี่ยน:** ดึงช่างเก่งมาสอนทำให้งานผลิตลดลง ชั้นใหญ่ลดต้นทุนแต่ feedback รายคนลดลง ต้องรักษาเพดานผู้เรียนต่อสถานี

**กฎเงิน/ตรวจรับ:** ไม่เพิ่ม aptitude หรือแกนมนุษย์ ไม่ฟาร์ม XP ด้วยการลงหลักสูตรเดิมซ้ำไม่จำกัด ต้องมีเวลาฝึก ความพร้อม และเกณฑ์ลดผลตอบแทนเมื่อเรียนซ้ำ

**เส้นทางโต:** หลักสูตรสั้นหนึ่งเรื่อง → สัญญาฝึกประจำ → หลักสูตรหลายระดับ → ฝึกและประเมินทักษะเฉพาะอุตสาหกรรม

## 10. โรงแรมธุรกิจและศูนย์ประชุม

**ขายอะไร:** ห้องพักสำหรับคนทำงานต่างพื้นที่ และพื้นที่ประชุม/อบรมตามช่วงเวลา ไม่ใช่หอพักสวัสดิการพนักงานในบทเดิม

**สิ่งที่ต้องมี:** อาคารห้องพัก แผนกต้อนรับ แม่บ้าน ผู้ดูแลอาคาร ระบบจอง และความปลอดภัย ห้องประชุมเปิดเพิ่มภายหลังได้

**ทรัพยากร/กลไกเพิ่ม:** `room_night`, `meeting_room_hour` เป็น capacity; `guest_amenity`, `cleaning_detergent`, `clean_linen_set`, น้ำ/ไฟเป็นต้นทุนจริง ผ้าลินินเป็น pool ที่ต้องซักหรือจ้างธุรกิจข้อ 4

**ขั้นตอน:** เสนอ/รับจอง → ยืนยัน/รับมัดจำ → เตรียมห้อง → check-in → ให้บริการ → check-out/ตรวจ → คิดค่าจริง/คืนส่วนเกิน → ทำความสะอาดก่อนเปิดขายอีกครั้ง

**ผลลัพธ์:** room-night ที่เข้าพักจริง รายได้ห้อง/ประชุม ความพึงพอใจ และงานทำความสะอาดค้าง ไม่คิดรายได้จากห้องว่างเป็นเงินที่สูญจริง

**ข้อแลกเปลี่ยน:** ลดราคาช่วยเติมห้องแต่ลูกค้าใช้ทรัพยากรเหมือนเดิม อีเวนต์เติมห้องเป็นช่วง ไม่ใช่อัตราเข้าพักเต็มตลอดปี

**กฎเงิน/ตรวจรับ:** ห้องเดียวกันขายคืนเดียวกันให้สองรายไม่ได้ ห้องยังไม่ทำความสะอาดหรือชำรุดไม่พร้อมใช้ ยกเลิก/no-show ใช้เงื่อนไขที่ประกาศก่อนจอง

**เส้นทางโต:** ที่พักขนาดเล็ก → ลูกค้าองค์กรประจำ → ห้องประชุม → แพ็กเกจอบรมร่วมศูนย์ฝึก/ขนส่ง

## 11. ผู้ค้าส่งและตัวแทนกระจายสินค้า

**ขายอะไร:** ซื้อสินค้าจากผู้ผลิตหลายรายแล้วขายต่อให้ร้านค้า/โรงงาน โดยทำกำไรจากการจัดหา ความพร้อมส่ง และเครดิต แยกจากโรงงานผลิตของตน

**สิ่งที่ต้องมี:** โกดัง พื้นที่รับ/หยิบ/แพ็ก ฝ่ายขาย จัดซื้อ คลัง QC รับเข้า เงินหมุน และรถหรือผู้รับขนส่ง

**ทรัพยากร/กลไกเพิ่ม:** สินค้าซื้อมาขายไปเก็บด้วย SKU/lot ที่อ้างสินค้าเดิม, `shipping_carton`, `packing_tape`, `pallet_asset`; เพิ่มเครดิตลูกค้า reorder point อายุเก็บ และต้นทุนถือครอง

**ขั้นตอน:** สำรวจ demand → ขอราคาผู้ผลิต → วาง PO → รับ/ตรวจ → เก็บตามล็อต → รับออเดอร์ลูกค้า → จอง/หยิบ/แพ็ก → ส่งมอบ → เก็บเงิน → วิเคราะห์ค้างสต็อก/สั่งเติม

**ผลลัพธ์:** กำไรค้าส่ง เครือข่ายร้านค้า ลูกหนี้/เจ้าหนี้ และความพร้อมสินค้า สินค้าถึงลูกค้าจริง ไม่ใช่ยอดขายที่เกิดทุกครั้งที่คลังเติม

**ข้อแลกเปลี่ยน:** ซื้อเยอะได้ส่วนลดแต่เงินจมและเสี่ยงตกรุ่น เครดิตช่วยขายแต่เสี่ยงเก็บเงินไม่ได้ CEO พิจารณารอบเงินสดและเครดิต ไม่ดู markup อย่างเดียว

**กฎเงิน/ตรวจรับ:** ย้ายของจากคลังเข้ากลุ่มบริษัทไม่สร้างกำไรใหม่ทั้งกลุ่ม ต้นทุนสินค้าตัดเมื่อขายตามวิธีประเมินที่เลือก ของฝากขายยังเป็นเจ้าของเดิมจนเกิดเหตุโอนตามสัญญา

**เส้นทางโต:** สินค้าไม่กี่ SKU → ตัวแทนเฉพาะอุตสาหกรรม → หลายผู้ผลิต → ศูนย์กระจายสินค้าหลายพื้นที่

## 12. บริการพลังงานแสงอาทิตย์และบริหารระบบให้ลูกค้า

**ขายอะไร:** ออกแบบ/ติดตั้งโซลาร์ สัญญาดูแล และระยะต่อไปลงทุนระบบแล้วขายพลังงานให้โรงงานตามสัญญา ต่างจากการติดโซลาร์ลดค่าไฟตนเองในบท 10

**สิ่งที่ต้องมี:** ทีมออกแบบ ช่างที่มีคุณสมบัติ เครื่องมือความปลอดภัย ผู้ตรวจ งานสำรวจหลังคา และสิทธิ์ใช้พื้นที่ตามสัญญา

**ทรัพยากร/กลไกเพิ่ม:** `solar_panel_asset`, `inverter_asset`, `mounting_rail`, `electrical_cable`, `protection_breaker`, `meter_asset`; battery เป็นทางเลือก ไม่บังคับทุกระบบ

**ขั้นตอน:** สำรวจโหลด/หลังคา → ออกแบบ/เสนอ → รับอนุมัติ/จองอุปกรณ์ → ติดตั้ง → ตรวจและทดสอบ → ส่งมอบ → ดูแล/อ่านมิเตอร์ → ออกบิลบริการหรือพลังงานตามรูปแบบสัญญา

**ผลลัพธ์:** ระบบผลิตพลังงานที่ติดตั้งจริง งานรับประกัน รายได้ติดตั้ง/ดูแล หรือ kWh ที่ขายและลูกค้าใช้จริง แยกรายได้อุปกรณ์กับบริการให้ตรงเจ้าของระบบ

**ข้อแลกเปลี่ยน:** รับติดตั้งใช้เงินหมุนน้อยกว่าถือระบบขายไฟเอง แต่รายได้หลังติดตั้งน้อยกว่า การถือระบบมีภาระลงทุน สภาพอากาศ ซ่อม และลูกหนี้ระยะยาว

**กฎเงิน/ตรวจรับ:** สมดุลพลังงาน = ผลิต + ซื้อ + คายแบต − ใช้ − ขาย − สูญเสีย − ชาร์จ ต้องตรง ไม่ขาย kWh เดียวกันสองครั้ง ประหยัดค่าไฟให้บริษัทตนเองไม่ใช่รายได้ภายนอก และไม่อ้างว่ามีสิทธิ์ขายไฟจริงโดยไม่ตรวจข้อกำหนดเชิงเกม

**เส้นทางโต:** สำรวจ/ล้างแผง → รับติดตั้ง → สัญญาดูแล → ระบบขายพลังงานตามสัญญา → บริหารหลายไซต์

## 13. วิธีประเมินเงินลงทุนและผลตอบแทนทุกธุรกิจ

ไม่กำหนดราคาตลาดจริงจากความจำ ให้ registry แยก:

- **ลงทุนเริ่ม:** ค่า asset + อาคาร/สถานี + ติดตั้ง/ทดลอง + stock เริ่มต้น + ค่ารับรองที่ต้องมี
- **เงินหมุนขั้นต่ำ:** เงินสดรายจ่ายในช่วงเก็บเงินที่คาด + เงินสำรองเหตุเสียหาย/งานแก้ − มัดจำที่ใช้ได้ตามสัญญา ห้ามนับมัดจำที่ต้องกันคืนเป็นทุนฟรี
- **ต้นทุนผันแปรต่อหน่วยขาย:** วัตถุดิบ/พลังงาน + บริการภายนอก + แรงงานจัดสรร + ค่าเสียหายตามงาน โดยแรงงานจัดสรรไม่ถูกจ่ายซ้ำกับ payroll
- **ส่วนเกินต่อหน่วย:** ราคาขายสุทธิ − ต้นทุนผันแปร จัดสรรต้นทุนคงที่แยกก่อนเรียกว่ากำไรสุทธิ
- **จุดคุ้มทุนเชิงปริมาณ:** ต้นทุนคงที่ต่อรอบ ÷ ส่วนเกินต่อหน่วย เมื่อส่วนเกินเป็นบวกและหน่วย/รอบเดียวกัน หากเป็นศูนย์หรือติดลบไม่คำนวณคืนทุนเป็นจำนวนบวก
- **ข้อจำกัดกำลัง:** ยอดคุ้มทุนต้องไม่สูงกว่างานที่คน เครื่อง พื้นที่ และตลาดทำได้จริง รวมเวลาตั้งเครื่อง เดินทาง พัก และ downtime

ตัวอย่างซักรีดสมมติค่าบริการ 18 บาท/กก. ต้นทุนผันแปรรวมที่จัดหมวดแล้ว 10 บาท/กก. และต้นทุนคงที่ 24,000 บาทต่อรอบ → ต้องขาย 3,000 กก./รอบจึงคุ้มทุนดำเนินงาน หากมีเครื่องทำได้เพียง 2,000 กก./รอบ โมเดลนี้ยังไม่คุ้มแม้เครื่องเต็ม ต้องปรับราคา ต้นทุน หรือกำลังอย่างมีหลักฐาน ตัวอย่างนี้ไม่รวมคืนเงินลงทุนเริ่มต้น

## 14. กลไกที่เพิ่มร่วมกันแล้วใช้ได้หลายธุรกิจ

| กลไก | ใช้กับธุรกิจ | ผลที่ควรเกิดจริง |
| :--- | :--- | :--- |
| ปฏิทินจอง asset/คน/พื้นที่ | เช่าเครื่อง ห้องพัก แล็บ รถ ทีมช่าง | กันชนเวลาและคำนวณคิวได้ |
| Custody และหลักฐานรับคืน | ขนส่ง ซักรีด เช่า แล็บ | ของลูกค้าไม่ปนของเราและตามความรับผิดได้ |
| สัญญาหลายงวด/สมาชิก/เงินประกัน | ซอฟต์แวร์ โรงแรม เช่า utility | เวลาเงินเข้าแตกต่างจากเวลาทำงาน |
| คุณภาพกับงานแก้ | ซักรีด บำบัดน้ำ แล็บ ซอฟต์แวร์ ช่าง | QC ไม่ผ่านมีคิวใหม่และต้นทุนใหม่ |
| ทักษะเฉพาะและคุณสมบัติงาน | รถ แล็บ ช่าง พลังงาน | คนเก่งทั่วไปไม่ทำงานเสี่ยงทุกแบบได้ทันที |
| Aging และการบำรุง | รถ เครื่องเช่า เครื่องซัก โซลาร์ | ยิ่งใช้งานยิ่งมีภาระดูแลตามแบบจำลอง |
| Demand และข้อเสนอคู่แข่ง | ทุกธุรกิจ | ไม่มีลูกค้าหรือไม่ชนะข้อเสนอไม่เกิดยอดขายฟรี |
| ข้อจำกัดน้ำ/พลังงาน/กากของเสีย | ซักรีด รีไซเคิล น้ำ พลังงาน | ใช้ทรัพยากรสมดุลและมีต้นทุนปลายทาง |

## 15. เครือข่ายธุรกิจที่บริษัทอาจเติบโตไปเอง

- **ขนส่ง → ซอฟต์แวร์:** บริษัทขนส่งซื้อ TMS เพื่อลดคิวผิดพลาด ต้องติดตั้ง/ฝึกและวัดผล ไม่ลดต้นทุนด้วยป้ายโบนัสทันที
- **โรงแรม → ซักรีด → บำบัดน้ำ:** ห้องมีคนพักสร้างงานซักจริง น้ำทิ้งสร้างภาระบำบัดจริง ถ้าบริษัทเดียวทำครบเป็นการโอนต้นทุนภายใน ไม่เพิ่มยอดขายรวมซ้ำ
- **โรงงาน → ทีมช่าง → เช่าเครื่อง:** เครื่องเสียสร้างความต้องการงานซ่อมหรือเครื่องทดแทน ทั้งสองทางเลือกมีคิว/ราคา ไม่บังคับซื้อบริการพร้อมกันทุกกรณี
- **โรงงาน → รีไซเคิล → ค้าส่ง:** เศษเกิดจริงถูกคัดและแปรเป็นวัตถุดิบเกรดที่ขายได้ ไม่สร้างเศษตั้งใจเพื่อปั๊มกำไรวงจร
- **ศูนย์ฝึก → ขนส่ง/แล็บ/ช่าง:** มีการฝึกที่ใช้เวลาเพิ่มทักษะภายนอกแกน แต่ใบเข้าเรียนอย่างเดียวไม่ให้สิทธิ์ทำงานอันตราย
- **พลังงาน → ทุกธุรกิจ:** ผลิต/ซื้อ/จ่ายไฟตามมิเตอร์ ความต้องการเพิ่มตามการใช้เครื่อง ไม่ลดค่าใช้จ่ายคงที่ทุกชนิดด้วยโบนัสพลังงาน

## 16. CEO ควรตัดสินใจเปิดหรือขยายเมื่อใด

เปรียบเทียบอย่างน้อย 3 ทางเลือก: ทำเอง จ้างภายนอก หรือรอ โดยดู demand ที่พิสูจน์ได้ ความสามารถทีม เงินสำรอง คิว asset และความเสี่ยงส่งมอบ ผลตอบแทนเป็นช่วง/หลายสถานการณ์ ไม่มองยอดขายวันเดียวเป็นอนาคตแน่นอน

มีขั้น `research → pilot → operating → expanding → winding_down` ที่ต่างกันชัดเจน pilot จำกัดทุน/ขนาด หยุดหรือขายสินทรัพย์ได้เมื่อไม่คุ้ม แต่ต้องจัดการงานค้าง เงินประกัน และการรับประกันก่อน

การใช้ธุรกิจร่วมกันต้องมี scheduler กลาง งานภายในอาจได้ลำดับสำคัญ แต่การผิดสัญญาภายนอกมีผลตามจริง ไม่เปิดทุกธุรกิจแล้วได้โบนัสซ้อนโดยไม่มีคนเพิ่ม

## 17. แผนพัฒนาที่แนะนำ

1. เพิ่มโครงสร้าง service contract, reservation, acceptance และ billing แบบเล็กก่อน ตรวจว่าต่อกับบัญชี/Save ได้โดยไม่เปลี่ยนสูตร core
2. ทดลอง **ขนส่งเหมาคันหนึ่งรถ** และ **ซอฟต์แวร์รับจ้างหนึ่งโครงการ** ตามบท 19/20 แยก feature flag และตรวจพฤติกรรมฐานเมื่อปิด
3. นำ reservation ไปใช้กับเช่าเครื่องและซักรีดก่อน เพราะวัด capacity, input และ output ได้ชัด
4. เพิ่มค้าส่ง ทีมช่าง และศูนย์ฝึกตามตลาด/คนที่รองรับ แล้วจึงเพิ่มแล็บ น้ำ โรงแรม พลังงาน และรีไซเคิลตามต้นทุนระบบเฉพาะ
5. เชื่อมธุรกิจเข้าหากันหลังทดสอบแต่ละธุรกิจแยกสำเร็จเท่านั้น จำนวนธุรกิจในเอกสารไม่ใช่คำสั่งให้ทำพร้อมกันทั้งชุด

แผนนี้เป็นคำแนะนำลำดับงาน ไม่ใช่แผน implementation ที่ผ่านออกแบบรายละเอียดหรือยืนยันระยะเวลาแล้ว

## 18. เกณฑ์ตรวจรับร่วมเมื่อเริ่มพัฒนา

- มีงานลูกค้าจริงตั้งแต่เสนอถึงรับเงิน และแยกมัดจำ ลูกหนี้ รายได้ ต้นทุน กับเงินสดได้
- ไม่มีคน/asset/สถานีทำสองงานเวลาเดียวกัน การหยุด/ยกเลิก/ซ่อมปลดจองเฉพาะสิ่งที่ควรปลด
- ทุกหน่วยขายมี input เวลา capacity และผลลัพธ์ที่พิสูจน์ได้ ไม่ใช้ PID/พอร์ตเปิดเป็นหลักฐานว่าธุรกิจทำงาน
- ประมวลผลคำสั่งซ้ำ ข้ามวัน และ save/load กลางสัญญาแล้วไม่สร้างเงิน ของ หรือบิลซ้ำ
- กรณีไม่มีลูกค้า ไม่มีพลังงาน คุณภาพไม่ผ่าน รับคืนล่าช้า และปิดกิจการต้องจัดการได้พร้อมเหตุผล
- บัญชีทรัพย์สินและของลูกค้าไม่ปนกัน การโอนภายในกลุ่มไม่เพิ่มกำไรกลุ่มซ้ำ
- เปิด snapshot/หน้าจอซ้ำไม่เปลี่ยน RNG; seed กับคำสั่งเดียวกันให้ผลเหมือนเดิม
- ปรับสมดุลจากกรณีกำไรและขาดทุนหลาย seed ไม่มีธุรกิจที่รับประกันคืนทุนโดยไม่ขึ้นกับ demand
