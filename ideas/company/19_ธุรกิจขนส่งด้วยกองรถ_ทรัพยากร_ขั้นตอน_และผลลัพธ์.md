# ธุรกิจขนส่งด้วยกองรถของบริษัท: จากรถคันแรกสู่เครือข่ายโลจิสติกส์

> สถานะ: **ข้อเสนอสำหรับอนาคต ยังไม่ได้พัฒนาในเกม**
>
> วันที่: 11 พฤศจิกายน 2026 · ฐานซอร์สที่ตรวจ: `main` commit `934a489`
>
> ID โครงสร้างข้อมูล สูตร ตัวเลข และช่วงราคาใหม่เป็นข้อเสนอเพื่อทดลองในเกม ไม่ใช่ API ปัจจุบัน ราคาตลาดจริง ประมาณการลงทุนจริง หรือผลทดสอบสมดุล

NPC/CEO เป็นผู้ลงทุน รับงาน จัดคน และดำเนินกิจการ ผู้เล่นเฝ้าดูผลและเหตุผล ขยายทักษะ/สถานะภายนอกแกนที่ล็อกไว้ ไม่แก้ `human-core.js` หรือ `CORE_LOCK.json` ทุกธุรกิจต้องใช้เงิน เวลา คน และทรัพยากรจริงใน simulation

## 1. สิ่งที่ต่อยอดจากบท 11 และสิ่งที่เพิ่ม

บท 11 มี Fulfillment ห้องเย็น และพิธีการศุลกากรแล้ว รายงานนี้เจาะธุรกิจที่บริษัท **ซื้อหรือเช่ารถเพื่อหารายได้จากการขนส่งให้ลูกค้าภายนอก** มีตัวรถ คนขับ เส้นทาง คิว การเติมพลังงาน ซ่อมบำรุง เอกสารส่งมอบ และเก็บเงิน ไม่ถือว่ามีอาคารคลังแล้วจะเกิดรายได้ขนส่งทันที

รถส่งของภายในกับรถรับจ้างต้องแยกการจอง capacity แม้ใช้รถคันเดียวกัน บริษัทอาจเสียรายได้ภายนอกเพื่อส่งสินค้าของตนให้ทัน แต่ห้ามนับเป็นรายได้ภายนอกทั้งสองฝั่ง

| :--- | :--- | :--- | :--- |
| เหมาคันโรงงานถึงโรงงาน | รถบรรทุกแห้ง จุดขึ้น/ลงของ | เที่ยว | โรงงานได้รับของครบในช่วงเวลานัด |
| ขนส่งร่วมหลายลูกค้า | จุดคัดแยกและงานจัดเส้นทางหลายจุด | พาเลท/กก. ตาม tariff ที่ระบุ | ลูกค้ารายเล็กส่งได้โดยไม่เหมาทั้งคัน |
| รถห้องเย็น | เครื่องทำความเย็น เซนเซอร์ และเชื้อเพลิงเพิ่ม | เที่ยวพร้อมเงื่อนไขอุณหภูมิ | อาหาร/เวชภัณฑ์พร้อม temperature log |
| หางพ่วง/ของหนัก | หัวลาก trailer ที่รองรับ และอุปกรณ์ยึด | เที่ยวตามน้ำหนักและชนิดของ | เครื่องจักรถึงปลายทางอย่างปลอดภัย |
| งานรอบประจำ | สัญญารายรอบและรถสำรอง | รอบที่ทำสำเร็จ | ร้านค้า/โรงงานได้รับของตามตาราง |

เริ่มรุ่นแรกด้วยเหมาคันสินค้าแห้ง ส่วนอื่นเป็นระยะขยาย โดยเฉพาะงานอันตรายต้องมีข้อกำหนดแยก ไม่อนุมานว่ารถทุกชนิดขนได้ทุกอย่าง

## 3. สิ่งที่ต้องมีเพื่อเปิดกิจการ

- **อาคารและพื้นที่:** ลานจอด สำนักงาน dispatch จุดตรวจรถ ช่องขึ้นลงสินค้า ทางเชื่อมถนน และพื้นที่กลับรถที่เข้าถึงได้
- **ทรัพย์สินถาวร:** รถอย่างน้อยหนึ่งคันและอุปกรณ์ยึดสินค้า รถแต่ละคันมีน้ำหนักบรรทุก ปริมาตร ชนิดพลังงาน และประวัติซ่อมของตนเอง
- **บุคลากร:** คนขับที่คุณสมบัติตรงรถ ผู้จัดเที่ยว และฝ่ายขาย/ธุรการ บริษัทเล็กให้คนทำหลายหน้าที่ได้ แต่คนเดียวขับรถกับคุมคลังพร้อมกันไม่ได้
- **เงิน:** ค่าซื้อ/เงินดาวน์ ค่าจดทะเบียน/สิทธิ์ประกอบการเชิงเกม เงินเชื้อเพลิง เงินเดือน ประกัน และเงินหมุนรอชำระบิล
- **การกำกับงาน:** แบบสัญญา ข้อจำกัดน้ำหนัก ความรับผิดสินค้า หลักฐานรับส่ง และรอบพักคนขับ เป็นระบบจำลอง ไม่อ้างว่าครบกฎหมายขนส่งจริง

กรอบลงทุนทดลอง: รถแห้งหนึ่งคัน 350,000–700,000 บาทเกม + ลาน/อุปกรณ์ 50,000–150,000 + เงินหมุนอย่างน้อย 30 วัน ค่าเหล่านี้ต้องปรับกับระดับเงินเดือนและอัตราเร่งเวลาเกมก่อนใช้ อย่าใส่ลง registry โดยไม่จำลองคืนทุน

## 4. วัตถุดิบและทรัพยากรที่เสนอ

| ID เสนอ | ประเภท/หน่วย | ใช้อย่างไร |
| :--- | :--- | :--- |
| `diesel_liter` | ของสิ้นเปลือง/ลิตร | ลดตามระยะจริง น้ำหนัก และการเดินเครื่อง |
| `charging_kwh` | บริการพลังงาน/kWh | สำหรับ EV ใช้เวลาชาร์จและ capacity หัวชาร์จจริง |
| `truck_tire` | อะไหล่/เส้น | เปลี่ยนตามสภาพ ไม่ใช้หนึ่งเส้นต่อทุกเที่ยว |

| `cargo_seal` | ของสิ้นเปลือง/ชิ้น | ใช้ผนึกเที่ยวที่ต้องมีหลักฐาน |

รถกับ trailer เป็น asset ไม่ใช่วัตถุดิบที่ถูกกินเมื่อสร้างงาน สินค้าลูกค้าเป็นทรัพย์สินฝากขน แยกจากสินค้าของบริษัทเสมอ

## 5. ขั้นตอนธุรกิจและสถานะงาน

1. **สำรวจความต้องการ:** ฝ่ายขายรับคำขอ ระบุจุดรับ/ส่ง ช่วงเวลา น้ำหนัก ปริมาตร ประเภทสินค้า และเงื่อนไขเสียหาย
2. **ประเมิน:** dispatch หาเส้นทางไปจุดรับ เส้นทางส่ง และทางกลับ ประเมินรถเปล่า ค่าผ่านทาง เวลารอ และ capacity
3. **เสนอราคา:** CEO/ฝ่ายขายเทียบกำไรคาดหมายกับความเสี่ยง เลือกรับ ปฏิเสธ หรือเสนอเวลาใหม่
4. **ยืนยันและจอง:** จองรถ คนขับ loading bay และพลังงาน สร้างใบงานโดยยังไม่ตัดของจากคลังลูกค้า
5. **ตรวจรถและโหลด:** ตรวจสภาพ/คุณสมบัติ นับของและบันทึกการรับฝาก ก่อนเริ่มออกเดินทาง
6. **เดินทาง:** ความคืบหน้าขึ้นกับระยะ ความเร็วเส้นทาง การจราจร การพัก และสภาพรถ ไม่ใช่ timer คงที่ทุกงาน
7. **ส่งมอบ:** เทียบจำนวนและสภาพกับหลักฐานรับฝาก ผู้รับยืนยันหรือสร้างข้อพิพาท/งานส่งซ้ำ
8. **ออกบิล:** เก็บเงินตามเงื่อนไขทันทีหรือเครดิต แยกรายได้กับกระแสเงินสด และป้องกันการออกบิลซ้ำ
9. **คืนรถและดูแล:** ปลดจอง ตรวจรถ เติมพลังงาน ทำความสะอาด และจัดรอบซ่อมก่อนรับงานต่อ

สถานะเสนอ: `quoted → reserved → loading → outbound → delivering → delivered → invoiced → paid`; แยก `cancelled`, `failed`, `claim_pending` และสถานะรถกลับ ไม่ให้ paid แปลว่ารถว่างทันที

## 6. กลไกเส้นทางและการคิดต้นทุน

ระยะรวมเที่ยว = ระยะรถเปล่าไปจุดรับ + ระยะบรรทุก + ระยะกลับ/ไปงานถัดไปที่ยืนยันแล้ว ห้ามสมมติว่ามี backhaul เสมอ

น้ำมันใช้ = `distanceKm × baseLitersPerKm × loadFactor` + น้ำมันระหว่างจอดเดินเครื่อง โดยทุก factor ต้องมีขอบเขตและไม่ให้ค่าเป็นลบ รถห้องเย็นมีพลังงานเครื่องเย็นเพิ่ม

ความจุรับได้ต้องผ่าน **ทั้งน้ำหนักและปริมาตร** รวมข้อจำกัดชนิดสินค้า รถ คนขับ และเวลารับส่ง การจองข้ามวันต้องกันเวลาเดินทางกลับด้วย

กำไรต่อเที่ยวก่อนค่าใช้จ่ายส่วนกลาง = ค่าขนส่งที่รับรู้ − พลังงาน − ค่าผ่านทาง − แรงงานเที่ยว − ค่าบริการภายนอก − ค่าเสียหายจริง ส่วนค่าเสื่อม ประกัน และค่าใช้จ่ายคงที่จัดสรรแยกเพื่อไม่หักซ้ำ

## 7. ตัวอย่างผลลัพธ์หนึ่งเที่ยว

เที่ยวไปส่ง 120 กม. กลับเปล่า 120 กม. ใช้น้ำมัน 0.18 ลิตร/กม. = 43.2 ลิตร ราคาทดลอง 32 บาท/ลิตร → 1,382.40 บาท รับค่าขนส่ง 4,500 บาท ค่าผ่านทาง 200 บาท และแรงงานจัดสรรเที่ยว 500 บาท

เหลือส่วนเกินก่อนค่าประกัน ค่าเสื่อม และส่วนกลาง = **2,417.60 บาท** ไม่ใช่กำไรสุทธิ หากคิดเฉพาะขาไปจะประเมินดีเกินจริง และห้ามหักค่าแรงจัดสรรนี้เป็นเงินสดซ้ำกับ payroll

**ผลลัพธ์ธุรกิจ:** เงินค่าบริการ ลูกหนี้ ประวัติส่งตรงเวลา ความไว้วางใจลูกค้า และระยะ/สภาพรถที่เปลี่ยนจริง ลูกค้าปลายทางได้รับของ ส่วนรถมีต้นทุนและภาระดูแลต่อเนื่อง

## 8. รถเสีย อุบัติเหตุ การขยาย และการเลิกกิจการ

รถเสียระงับงานที่เกี่ยวข้อง dispatch อาจส่งรถสำรองหรือจ้างช่วงโดยเสียต้นทุนและเวลา การเคลมประกันมีวงเงิน ค่าเสียหายส่วนแรก เงื่อนไข และเวลารอ ไม่รับเงินคืนครบอัตโนมัติ

CEO ซื้อรถเพิ่มเมื่อมีงาน/ข้อเสนอที่มีหลักฐานและเงินหมุนพอ เปรียบเทียบซื้อ เช่า และจ้างช่วง ห้ามซื้อเพิ่มจาก utilization สูงเพียงวันเดียว ถ้าขายรถต้องปลดภาระงาน ซ่อม/รับช่วงสัญญา และคิดยอดหนี้คงเหลือให้ครบ

ลำดับขยาย: รถแห้งหนึ่งคัน → สัญญารอบประจำ → รถหลายคัน → รวมเที่ยวหลายลูกค้า → ห้องเย็น/หัวลาก → คลังพักสินค้า เชื่อมบท 11 โดยไม่บังคับซื้อคลังระดับ 3 ก่อนเปิดขนส่งพื้นฐาน

## 9. การเชื่อมเกมและเกณฑ์ตรวจรับ

เสนอ `vehicleRegistry`, `routeGraph`, `freightContract`, `cargoCustody`, `vehicleReservation`, `driverDuty` ภายนอกแกนเดิม ตรวจสิ่งที่มีใน catalog ก่อนตั้ง ID ใหม่ ใช้ `data.js` เก็บชนิดรถ/กฎ, `sim.js` จัดงาน, `economy.js` ลงบัญชี, `layout.js` เชื่อมทางเข้า, `api.js`/UI แสดง และ `save.js` ตรวจความสัมพันธ์

- รถ/คนขับเดียวกันไม่มีงานทับเวลา สินค้าลูกค้าไม่กลายเป็น opening stock ของเรา
- ขากลับเปล่าและการรอมีต้นทุน; รถเกินน้ำหนักหรือผิดประเภทรับงานไม่ได้
- เติมพลังงาน ซ่อม เคลม ส่งซ้ำ ออกบิล และจ่ายบิลซ้ำไม่เพิ่มเงิน/ของซ้ำ
- บันทึก/โหลดระหว่างเดินทางรักษาเวลา สินค้า ความรับผิด และการจอง
- ทดสอบภายหลังทั้งงานกำไร งานขาดทุน งานยกเลิก รถเสีย และลูกหนี้ค้าง; ไม่มีคำรับประกันว่าซื้อรถแล้วจะคุ้มทุนทุก seed
