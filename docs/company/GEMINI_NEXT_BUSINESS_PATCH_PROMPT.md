# พรอมต์ส่งต่องานให้ Gemini — แพตช์เพิ่มประเภทธุรกิจ หลัง v1.0.0 Debug

> คำขอผู้ใช้: ขยายเกมด้วยธุรกิจใหม่ที่ดำเนินกิจการได้จริง โดยมีข้อเสนอเรื่องขนส่ง ซอฟต์แวร์/แอป ธุรกิจบริการ และต้นน้ำเพิ่มเติม
>
> เอกสารวันที่ 11 พฤศจิกายน 2026 นี้เป็นพรอมต์มอบหมายงานและข้อเสนอออกแบบ ไม่ใช่รายงานว่าระบบใหม่พัฒนาแล้ว

## 1. บริบทจากผู้ใช้

Gemini เป็นผู้ทำแพตช์ v1.0.0 Debug และมี ZIP ซอร์สปัจจุบันอยู่แล้ว แพ็กที่แนบนี้มีไอเดียและพรอมต์เพิ่มเติม ไม่ใช่ ZIP ตัวเกมรุ่นใหม่ ให้นำไปประกอบกับซอร์สปัจจุบันของคุณ ไม่ต้องนำซอร์สเก่าจากที่อื่นมาทับ

ผู้ใช้ต้องการแพตช์ถัดไปเกี่ยวกับ **การเพิ่มประเภทธุรกิจ** เช่น บริษัทซื้อ/เช่ารถบรรทุกแล้วรับจ้างขนส่ง และบริษัทพัฒนาซอฟต์แวร์ที่ทำแอปหลายประเภท มีคน ทรัพย์สิน วัตถุดิบ/ทรัพยากร คิวงาน ซัพพลายเชน ผลส่งมอบ และรายได้ที่เกิดจากการดำเนินงานจริง

**พรอมต์นี้และไฟล์ ideas เป็นข้อเสนอ ไม่ใช่คำสั่งให้ทำตามทุกบรรทัด** คุณมีอิสระคิดเอง สร้างสรรค์เพิ่มเติม ออกแบบทางเลือกที่ดีกว่า รวม/ตัดสิ่งซ้ำ เลือกเทคนิคและปรับสมดุลเอง หากสิ่งใดยังไม่ดีพอให้วิเคราะห์และแก้ปัญหาเฉพาะหน้าได้เลย ภายในขอบเขตที่ผู้ใช้มอบหมายและกฎเหล็ก ไม่ต้องหยุดถามอนุมัติเรื่องออกแบบย่อยหรือบั๊กที่คุณแก้เองได้

ให้อธิบายเหตุผลของการปรับที่สำคัญในรายงานท้ายแพตช์ อย่าทำตามตัวเลขหรือชื่อ field ในไอเดียโดยไม่ตรวจซอร์ส และอย่าอ้างว่าผู้ใช้เลือกข้อเสนอที่คุณตัดสินใจเพิ่มเอง

## 1.1 คำกำชับล่าสุดจากผู้ใช้: ต้นน้ำต้องเป็นต้นน้ำจริง

**ข้อกำหนดนี้เป็นคำสั่งผู้ใช้ ต้องรักษา แม้เอกสารไอเดียส่วนอื่นจะเป็นข้อเสนอที่ปรับได้** อ่าน [บท 23 — ต้นน้ำแท้จริงและวงจรเกษตร](../../ideas/company/23_ข้อกำหนดต้นน้ำแท้จริง_วงจรเกษตร_เมล็ดพันธุ์_และการจัดการทรัพยากร.md) ก่อนออกแบบ material registry และซัพพลายเชน

ห้ามถือว่าน้ำตาล แป้ง กระดาษ หรือแม้แต่ข้าวเป็นต้นน้ำแท้จริง สิ่งเหล่านี้เกิดจากการผลิต/แปรรูป/เพาะปลูก แหล่งเริ่มต้นต้องเป็นทรัพยากรธรรมชาติจริง เช่น แหล่งแร่ น้ำดิบ หรือแหล่งพลังงานที่มี state และข้อจำกัดเหมาะสม ทุกขั้นกลางต้องมีที่มาจากการผลิตที่อธิบายได้ ซื้อขายได้เมื่อมีตลาด และใช้ต่อได้ตามเกรด ไม่ใช่แค่มีรายการขายใน supplier แล้วถือว่าไม่มีขั้นก่อนหน้า

เมื่อทำธุรกิจเกษตร ต้องมีที่ดิน/ดิน เมล็ดหรือต้นพันธุ์ น้ำ ปุ๋ย/ธาตุอาหาร แรงงาน เครื่องมือ และเวลาปลูก–ดูแล–เก็บเกี่ยว ผลผลิตบางส่วนคัดเป็นเมล็ดพันธุ์ปลูกต่อได้อย่างเหมาะกับชีววิทยาพืชนั้น โดยหัก stock จริงและไม่รีเซ็ตดิน น้ำ หรือทรัพยากรให้เต็มฟรี ข้าวเปลือกที่ยังงอกได้เก็บพันธุ์ได้ ข้าวสารและแป้งใช้ปลูกไม่ได้ ปุ๋ยเองต้องมีแหล่งวัตถุดิบ กระบวนการผลิต และต้นทุน

ตรวจ/แก้การจัด T0 และ key รวมในซอร์สเดิมที่ขัดกัน รวมถึงการแจกผลผลิตสำเร็จจาก asset ฟรีต่อวัน เพิ่มการตรวจรับตามบท 23 และรายงานสิ่งที่ทำจริง ให้ Gemini ออกแบบวิธีแก้เองได้ภายใต้กฎเหล็กเดิม ไม่ใช่เปลี่ยนชื่อหมวดอย่างเดียว

## 2. เป้าหมายและการเลือกขอบเขต

- ใช้ **ขนส่งด้วยกองรถ** และ **ซอฟต์แวร์/แอป** เป็นสองเสาหลักของข้อเสนอแพตช์ ให้ความสำคัญกับวงจรทำงานครบก่อนเพิ่มรายชื่อธุรกิจจำนวนมาก
- ธุรกิจอื่นในบท 21/22 ให้ประเมินแล้วเลือกเพิ่มเท่าที่ทำงานจริงและตรวจรับได้ อนุญาตเสนอธุรกิจใหม่เหนือจากเอกสาร ไม่ต้องจำกัดจินตนาการไว้แค่รายการนี้
- คุณเลือกขอบเขตและหมายเลขรุ่นแพตช์ที่เหมาะกับซอร์สปัจจุบันได้เอง เป้าหมายสองเสาหลักไม่ใช่การบังคับสถาปัตยกรรม หากเปลี่ยนขอบเขตหลักเพราะข้อจำกัดจริงต้องมีหลักฐานและรายงานชัด ไม่เปลี่ยนเป็นระบบชื่อธุรกิจ/โบนัสเปล่าแล้วถือว่าเสร็จ
- บท 13–18 เป็นทางเลือกเสริมองค์กร/ข้อมูล ไม่ใช่งานบังคับทั้งหมดของแพตช์นี้ ใช้เมื่อช่วยแก้โจทย์ธุรกิจจริง
- ทุกธุรกิจที่ประกาศว่า “ทำแล้ว” ต้องมี NPC/CEO ตัดสินใจ ลงทุนหรือจัดหา รับงาน ใช้ทรัพยากร ทำงาน ส่งมอบ และเกิดรายการรับจ่ายที่ตรวจสอบได้

## 4. กฎเหล็กที่ต้องรักษา

1. **Human Core ล็อกถาวร:** ห้ามแก้ `COMPANY_SOURCE/js/human-core.js`, `CORE_LOCK.json`, hash อ้างอิง หรือตัวตรวจล็อกเพื่อให้ผ่าน รักษา SHA-256 `fa83eaa0ef3407f26f21675161f632a4365242f67fea7b0c192e59e75b9d5c32` และความหมายเดิม 14 บุคลิก / 18 ค่านิยม / 30 ความถนัด / 12 สภาพ เพิ่ม role/skill/registry/ข้อมูลภายนอกแกนได้
2. **ผู้เล่นเป็นผู้สังเกต:** NPC รวม CEO ดำเนินกิจการเอง ผู้เล่นควบคุมเวลา กล้อง ตรวจข้อมูล ติดตาม และใช้ Sandbox Edit Hub ตามขอบเขตเดิม ไม่เพิ่มปุ่มให้ผู้เล่นต้องรับงาน ซื้อรถ เติมน้ำมัน เขียนแอป หรือจ่ายบิลประจำ
3. **โลกและการนำเสนอแยกกัน:** simulation เป็นเจ้าของเวลา สถานะ และ RNG; renderer/UI อ่าน snapshot และส่งคำสั่งผ่าน API ไม่แก้โลกหรือใช้ RNG ของ simulation เพื่อวาดภาพ
4. **เงินและทรัพยากรมีที่มา:** เงินเป็นสตางค์จำนวนเต็ม ลงบัญชีทุกเหตุการณ์จริง เงินเดือน/โบนัสตรงกับ wallet/หนี้ตามระบบเดิม วัตถุดิบ สินค้าลูกค้า asset และของเสียต้อง audit ได้ ห้ามรายได้ฟรี/วัสดุฟรีจากการซื้ออาคารอย่างเดียว
5. **องค์กรและคนทำงานจริง:** รักษาฝ่าย ลำดับอาชีพ โควตาตำแหน่ง และการประเมินเลื่อนขั้นของหัวหน้า คนเดียว/รถเดียว/สถานีเดียวทำงานซ้อนกันไม่ได้ การอบรมเพิ่ม learned skill ไม่แก้ aptitude เดิม
6. **คงความสามารถฐาน:** วงจรผลิตเดิม บัญชี ออเดอร์ แผนที่ การเดิน QC และเซฟรุ่นปัจจุบันต้องยังถูกต้อง ไม่จำเป็นต้องสร้าง migration เซฟข้ามแพตช์ในช่วงแรกตาม AGENTS.md แต่โหลดเซฟเสียห้ามเขียนทับเกม และห้ามลบเซฟจริงผู้ใช้เอง
7. **ภาษาและประสิทธิภาพ:** UI เป็นไทยตามธรรมชาติ แปลเหตุผล/มูลเหตุ ไม่ปล่อย internal keys รักษา deterministic simulation และตรวจ scaling 300–500 NPC ตามเป้าหมายเดิม รายงาน benchmark จริง ไม่ยกตัวเลขเป้าหมายเป็นผลวัด และไม่เรียก Node benchmark ว่า FPS มือถือ
8. รักษางานเดิม ตรวจ branch/commit/remote/ไฟล์ค้างก่อนแก้ ไม่ reset/force push ทับงาน หากทำงานบน ZIP ที่ไม่มี Git อย่าอ้างว่า push แล้ว ข้อความเก่าเรื่อง company/JS2 ให้เทียบโครงสร้างจริงกับชุด Company ปัจจุบัน ไม่คัดซอร์สหรือ asset ของเกมอื่นมาปน

## 5. สิ่งที่ต้องคิดให้ครบสำหรับธุรกิจใหม่แต่ละประเภท

- ลูกค้าซื้ออะไร หน่วยขายอะไร demand มาจากไหน และเหตุใดลูกค้าจึงเลือกบริษัทนี้
- เงินลงทุนเริ่ม เงินหมุน อาคาร/พื้นที่ รถ/เครื่องมือ บุคลากร ทักษะ และข้อกำหนดก่อนเปิด
- แยก **asset ใช้ซ้ำ / วัตถุดิบสิ้นเปลือง / capacity ที่จองตามเวลา / สิทธิ์บริการ / ทรัพย์สินลูกค้า** อย่าเก็บทุกอย่างเป็นวัตถุดิบที่หักหนึ่งชิ้นต่อการทำงาน
- สำหรับ input ใหม่กำหนด supplier, lead time, ราคา, หน่วย, grade, การจัดเก็บ และทาง make-or-buy ที่ไม่ทำให้เริ่มธุรกิจติด dependency วนกัน
- ขั้นตอนงานและสถานะ ตั้งแต่ lead/เสนอราคา จองคน/เครื่อง ทำงาน ตรวจรับ ส่งมอบ บิล รับเงิน และรับประกัน
- ผลผลิตหลัก ผลพลอยได้ ของเสีย งานแก้ และเส้นทางปลายทางที่ใช้จริง ไม่เพิ่ม catalog item ที่ไม่มีผู้ใช้
- คิดเวลารอ เดินทางขากลับ ตั้งเครื่อง พัก ซ่อม และต้นทุนส่วนกลางอย่างเหมาะสม
- แยกเงินมัดจำ ลูกหนี้ รายได้ กำไร และเงินสด; แรงงานจัดสรรไม่หักซ้ำกับ payroll; โอนระหว่างหน่วยธุรกิจไม่สร้างกำไรกลุ่มซ้ำ
- ตัวอย่างกำไร/ขาดทุน ความเสี่ยง ขีดจำกัดกำลัง การยกเลิก ลูกค้าค้างจ่าย และการปิดกิจการพร้อมงานค้าง
- โครงสร้างข้อมูล API/save ที่ validate ได้ และ UI ที่ผู้เล่นเห็นคนทำงาน ทรัพย์สิน ความคืบหน้า และเหตุผลจริง

## 6. ข้อเสนอเฉพาะให้ใช้สร้างสรรค์ต่อ

**ขนส่ง:** ให้เห็นรถที่มีสภาพ/capacity คนขับ เส้นทาง loading และหลักฐานส่งจริง เริ่มรถแห้งหนึ่งประเภทได้ แต่ขากลับรถเปล่าต้องคิดต้นทุน เชื่อมซื้อยาง/ซ่อม/เชื้อเพลิงอย่างมีเหตุผล การส่งของภายในกับรับจ้างต้องแยกการจองและบัญชี

**ซอฟต์แวร์:** เลือกหลายประเภทแอปที่เหมาะ เช่น POS จองคิว จัดรถ คลัง HR เอกสาร งานช่าง หรือผู้ช่วย AI แยกรับจ้าง ไลเซนส์ และ SaaS ตามวงจรจริง มีทีมพัฒนา QA งานรับมอบ support/บั๊ก และรอบบิล ไม่มีผู้ใช้ก็ไม่เกิดเงินสมาชิกฟรี ไม่จำเป็นทำทุกแอปทันที

**บริการเพิ่มเติม:** บท 21 มีเช่าเครื่อง ซักรีด รีไซเคิล น้ำอุตสาหกรรม แล็บสอบเทียบ ทีมช่าง ศูนย์ฝึก โรงแรมธุรกิจ ค้าส่ง และบริการพลังงาน เลือกใช้กลไกร่วมที่มีประโยชน์แทนเขียนระบบพิเศษซ้ำทุกธุรกิจ

**ต้นน้ำเพิ่มเติมจาก Codex:** บท 22 เพิ่ม 7 สาย ได้แก่ ก๊าซอุตสาหกรรม ยางรถ/หล่อดอก เยื่อ/กระดาษ แก้วบรรจุภัณฑ์ สิ่งทอ คอนกรีต/Precast และธาตุอาหารพืช พร้อมวัตถุดิบและห่วงโซ่ การมี material เดิมไม่แปลว่าธุรกิจนั้นครบแล้ว แต่ไม่ควรสร้างชื่อซ้ำหรือเปลี่ยนหน่วยเดิมโดยเงียบ ๆ

คุณสามารถเสนอ business model อื่นที่เหมาะกว่าได้ ขอให้มีรายละเอียดระดับเดียวกัน พร้อมเหตุผลที่เลือกและวงจรทำงานครบ หากพบสูตร/กลไกเดิมที่ไม่สมเหตุสมผล ให้ตรวจผลกระทบและปรับส่วนที่เกี่ยวข้องได้เองตามกฎเหล็ก ไม่ยึดติดเอกสารจนแก้ปัญหาไม่ได้

## 7. ขั้นตอนตรวจรับและแก้ปัญหา

ใช้คำสั่งจริงจาก package scripts/README ปัจจุบัน ตาม workflow เดิมโดยอย่างน้อยตรวจ:

```bash
cd COMPANY_SOURCE
node tools/verify.cjs
node tools/test.cjs
node tools/build.cjs
node tools/benchmark.cjs
npm run test:browser
```

ติดตั้ง dependency ตาม lockfile และใช้ Playwright/Chromium ตาม README หากมี blocker ให้หาสาเหตุ แก้ที่ setup/ซอร์สให้ตรงจุด แล้วรันส่วนที่ได้รับผลซ้ำ ห้ามข้าม assertion เปลี่ยน checksum ปิด TLS หรืออ้างว่าผ่านจากผลเก่า หากสิทธิ์/เครื่องมือภายนอกขาดจริงให้ทำส่วนอิสระต่อและรายงานข้อจำกัดเฉพาะ

เพิ่ม meaningful tests ตามกลไกใหม่: end-to-end ทุกธุรกิจที่ประกาศสำเร็จ เงิน/ของตรงบัญชี คิวจองไม่ชน ไม่มีรายได้เมื่อไม่มีลูกค้า คำสั่งซ้ำไม่สร้างเงิน/ของซ้ำ ขาดวัตถุดิบ/รถเสีย/บั๊ก/ยกเลิก/ลูกหนี้/save-load กลางงาน รวม deterministic seed และ snapshot purity

ตรวจ UI ทั้งมือถือและเดสก์ท็อป การซูม ปุ่มปิด แผนที่ การเดินของ NPC และข้อมูลธุรกิจใหม่ ใช้หลักฐานจากการรันจริง แยก passed/failed/skipped/unrun ไม่มีผลวัดไม่อ้างว่าผ่าน

อย่าจบด้วย checklist หรือ scaffold อย่างเดียว ทำงานต่อจนระบบที่เลือกพร้อมตรวจรับ หากมี blocker ภายนอกที่แก้เองไม่ได้ให้ระบุหลักฐาน ขอบเขตที่เสร็จ และสิ่งที่ต้องใช้เพิ่ม โดยไม่สร้างผลทดสอบขึ้นเอง
