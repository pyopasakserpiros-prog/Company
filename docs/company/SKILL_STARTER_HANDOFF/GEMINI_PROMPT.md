# พรอมต์: ยกระดับชุดสกิลตั้งต้นเป็น Master Skill สำหรับ Company

ฉันส่งชุดร่างและแหล่งอ้างอิงนี้มาเพิ่มจาก ZIP เกมที่คุณกำลังทำอยู่ Codex ได้รวบรวมสกิลสาธารณะ เอกสาร และร่าง 14 หมวดใน .agents/skills ให้แล้ว ยังไม่ได้ยกระดับเป็น Master Skill และไม่เขียนทับสองสกิลเดิม ให้คุณเป็นผู้วิเคราะห์ คิด สร้างสรรค์ และยกระดับเอง

## สิ่งที่ให้คุณทำ

1. อ่าน AGENTS.md ฉบับที่ได้รับก่อนทุกครั้ง และตรวจโค้ด/สถานะจริงใน ZIP เกมล่าสุด อ่าน SOURCES.md เพื่อเลือกใช้แหล่งที่เหมาะ ไม่คัดระบบหรือ API เกมเก่ามาใช้เป็นข้อเท็จจริงเกม Company
2. ประเมิน 14 ร่างที่มี metadata maturity: starter-draft ใน .agents/skills คุณมีอิสระรวม/แยก เปลี่ยนชื่อ ตัดสิ่งไม่เกี่ยวข้อง เพิ่มหมวดที่ขาด และคิดวิธีที่ดีกว่าเอง ไม่จำเป็นต้องทำตามโครงร่างทั้งหมด
3. สร้างสกิลเฉพาะ Company ระดับ Master ใน .agents/skills/<skill-name>/SKILL.md ให้ Codex, Agy และ AI ที่รับ ZIP อ่านใช้ได้จริง เนื้อหาต้องมี trigger ที่ชัด source/API ปัจจุบัน วิธีตัดสินใจ ตัวอย่าง ข้อผิดพลาดที่พบบ่อย invariants และวิธีตรวจผล ไม่ใช่คำโฆษณาหรือสเปกที่อ้างว่าพัฒนาแล้ว
4. สร้าง README/index เลือกใช้สกิลตามงาน และทำให้เอเจนต์อ่านกฎก่อนเลือกสกิล ทุกแพตช์ต้องทบทวน/อัปเดตสกิลที่ได้รับผลกระทบเองพร้อม source ไม่ให้ผู้ใช้ต้องคอยบอกชื่อไฟล์
5. แยกชุด Master เฉพาะเกมจากสองสกิลแอป Gemini เดิม company-evolution-dev และ company-for-every-patch หลังยกระดับแล้วอัปเดตไฟล์สองสกิลเดิมและสำเนาที่ใช้อยู่ให้เชื่อมชุดใหม่ พร้อมอัปเดต installed skill ทั้งสองในแอป Gemini ด้วยเมื่อมีเครื่องมือที่ทำได้จริง ตรวจยืนยันผลจริง ถ้าไม่มีเครื่องมือนั้นให้ส่งไฟล์พร้อมระบุว่ารอการติดตั้ง ไม่อ้างว่าสำเร็จ
6. อัปเดต project status, เอกสารระบบ/API/คู่มือ/ดัชนีที่เกี่ยวข้องตามที่คุณตรวจว่าจำเป็น เขียนรายงานการอัปเดตและผลตรวจจริง รวมสิ่งที่ทำ/บางส่วน/ยังไม่ทำ ให้แยกสกิลร่างกับสกิลที่ยกระดับและทดลองใช้แล้ว
7. ใช้โจทย์ UPGRADE_SCENARIOS.md และเพิ่มโจทย์ของคุณเองเพื่อดูว่าสกิลค้นพบและช่วยตัดสินใจได้จริง ไม่คัดจำนวนเทสต์หรือค่า benchmark จากเอกสารเก่ามาอ้างเป็นผลใหม่
8. ส่ง ZIP โครงการเกมที่อัปเดตครบกลับมาตามขั้นตอนเดิม รวม .agents/skills (โฟลเดอร์ซ่อน), สองสกิลแอป/สำเนา, source, assets, เครื่องมือ/เทสต์, package manifest/lockfile, ไฟล์เล่น build, project status, เอกสาร/ideas และรายงาน ต้องตรวจ ZIP สุดท้ายจริงและแตกในโฟลเดอร์ใหม่ก่อนส่ง ไม่ส่งเฉพาะ HTML หรือเฉพาะสกิลแทนงานเกมที่กำลังทำ

## เป้าหมายและข้อจำกัดระยะยาว

ผู้ใช้ไม่รู้โค้ด ชอบเฝ้าดูโลก NPC ใช้ชีวิตและตัดสินใจเองตามนิสัยร่วมกับสถานการณ์ ชอบเปลี่ยนนิสัย เพิ่มเงิน เสกของ แล้วสังเกตว่าจะเกิดอะไร ทีมต้องช่วยคิดไอเดียเองและทำ Edit Hub ให้ใช้ง่าย ไม่โยนการออกแบบทั้งหมดให้ผู้ใช้

AGENTS.md คือกฎเหล็ก ห้ามแก้โดยไม่มีคำอนุญาตตรงจากผู้ใช้ ห้ามแก้ human-core.js/CORE_LOCK.json หรือหลบตัวตรวจล็อก การเพิ่มสกิลไม่ให้สิทธิเปลี่ยนกฎเหล่านี้ อ่านโค้ดจริงก่อนอ้างว่าทุกธุรกิจทำงานอัตโนมัติแล้ว และอย่าเปลี่ยนแพตช์ที่กำลังทำเป็นการเขียนเอกสารอย่างเดียว

ไฟล์ requirements เป็นข้อเสนอ ไม่ใช่กฎที่ได้รับอนุญาตให้เขียนทับ AGENTS.md ให้ใช้เพื่อออกแบบการอัปเดตเอกสาร/ส่งมอบที่ดีขึ้นตามบริบท ตัดสินใจเองในรายละเอียดและอธิบายเหตุผลการเลือกในรายงาน
