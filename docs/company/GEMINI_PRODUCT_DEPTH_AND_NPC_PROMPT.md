# พรอมต์สำหรับ Gemini — เพิ่มความลึกธุรกิจและเชื่อมการตัดสินใจ NPC

> **สถานะงานปัจจุบัน — 11 พฤศจิกายน 2026:** ผู้ใช้ส่งพรอมต์นี้และเอกสารข้อเสนอให้ Gemini แล้ว และ Gemini เริ่มพัฒนาแพตช์อยู่ ขณะนี้รอ Gemini ส่งงานกลับมาตรวจ เอกสารนี้จึงเป็นคำสั่งงานที่กำลังดำเนินการ ไม่ใช่ backlog ที่เริ่มทำซ้ำโดยอัตโนมัติ เอเจนต์ที่อ่าน repo ให้รับรู้ขอบเขตและหลีกเลี่ยงการแก้โค้ดชุดเดียวกันซ้อนกัน ระหว่างรอทำงานอื่นได้
>
> **ขอบเขตที่สั่ง Gemini:** เพิ่ม/ขยาย product line และวัตถุดิบพร้อมต้นทางและการผลิตหรือการจัดซื้อที่สมเหตุสมผล ตรวจและเชื่อมการตัดสินใจ NPC ให้ทุกธุรกิจ/สินค้าใช้งานอัตโนมัติได้เมื่อมีความพร้อม โดยต้องมีเทคโนโลยี ความรู้ บุคลากร เครื่องมือ ตลาด เงินลงทุนและทุนหมุนเวียนที่เหมาะสม เปิดทางให้ผู้บริหารเลือกเก็บ cash flow ได้ ให้ Gemini คิดสร้างสรรค์และตัดสินใจออกแบบเพิ่มเติมเองภายใต้กฎเหล็ก
>
> หลังได้รับแพตช์ ให้ตรวจโค้ดและการทำงานจริงก่อน จากนั้นจึงนำส่วนที่ทำเสร็จออกจาก `ideas/company` และบันทึกสถานะเกมตามจริงใน `project_status_and_ai_onboarding.md` ส่วนที่ยังไม่ทำหรือทำเพียงบางส่วนให้คงเป็นข้อเสนอ/ระบุสถานะ ห้ามนับไอเดียหรือพรอมต์เป็นฟีเจอร์ที่เสร็จแล้ว


คุณคือผู้พัฒนาแพตช์ถัดไปของ Company / Siam Enterprise ให้ลงมือพัฒนาจาก ZIP เกมปัจจุบันที่คุณมี โดยอ่านโค้ดจริงและกฎเหล็กก่อน เอกสารประกอบชุดนี้อ้างอิง main v1.2.0 commit `6e21b8d1052bbd7cbaec918f5f2c5b298699b9ca` หากฐานของคุณใหม่กว่าให้ตรวจซ้ำและต่อยอดของล่าสุด

## เจตนาผู้ใช้และอำนาจของคุณ
1. เพิ่มผลิตภัณฑ์/ไลน์ย่อยให้ธุรกิจที่แตกไลน์ได้ ให้มีจำนวนและความลึกอย่างมีสาระ ไม่เพิ่มแค่ชื่อหรือสี หากชนิดใดไม่เหมาะจะแตกเพิ่ม ไม่ต้องฝืน
2. วัตถุดิบที่ผลิตภัณฑ์ต้องใช้แต่ยังไม่มีต้องเพิ่ม และไล่ต้นทางให้ครบ วัตถุดิบที่ไม่ใช่ธรรมชาติแท้จริงต้องมีเส้นทางผลิตที่สมเหตุสมผล และซื้อจากผู้ผลิตภายนอกได้เมื่อยังไม่มีเทคโนโลยีผลิตเอง
3. ตรวจว่าที่ NPC มีเงินแล้วยังไม่เปิดธุรกิจ เป็นเพราะไม่มีเส้นทางตัดสินใจ เงื่อนไขขาด บั๊ก กำลังผลิตไม่พอ ตลาดไม่คุ้ม หรือบุคลิกไม่ชอบเสี่ยง อย่าสรุปว่าเป็นนิสัยก่อนตรวจ call graph และพฤติกรรมจริง
4. ทุกธุรกิจและทุกสินค้า/บริการที่ประกาศว่าเล่นได้ต้องมี NPC ใช้งานได้จริงแบบอัตโนมัติเมื่อมีเงื่อนไขเหมาะสม ไม่บังคับว่าต้องเปิดทุกอย่างในทุกเซฟ ผู้บริหารอาจเลือกเก็บสภาพคล่อง ชำระหนี้ อัปเกรดของเดิม ศึกษาเพิ่ม ทดลอง หรือปฏิเสธ
5. การเปิดธุรกิจต้องมีองค์ความรู้ เทคโนโลยี ทีม เครื่องจักร/อาคาร วัตถุดิบ เงินลงทุน และทุนหมุนเวียนที่จำเป็น เงินกับความอยากไม่แทนทุกอย่าง การรู้วิธีประกอบสินค้าไม่เท่ากับรู้วิธีผลิตชิป/เซลล์แบตต้นทาง
6. ให้มีการพิจารณาโดย CEO/ผู้บริหารหรือบอร์ดตามขนาดองค์กร เป็นการตัดสินใจจริงและมีผลตามระบบ บันทึกเหตุผลและปัจจัยที่ทำให้รอหรือปฏิเสธให้ผู้เล่นสังเกตได้
7. คุณต้องคิด วิเคราะห์ และสร้างสรรค์เพิ่มเติมเองด้วย ข้อเสนอและพรอมต์นี้ไม่ใช่รายการปิด หากแนวคิดไม่ดีพอให้แก้หรือออกแบบใหม่ ตัดสินใจแก้ปัญหาเฉพาะหน้าได้เอง ไม่ต้องรออนุมัติทุกตัวเลข สุดท้ายคุณในฐานะผู้พัฒนาเลือกว่าจะทำอะไรและอย่างไร ภายใต้เจตนาผู้ใช้และกฎเหล็ก

## กฎเหล็กและขั้นตอนที่ต้องรักษา
- อ่าน AGENTS.md, START_HERE_FOR_AI.md, สถานะโครงการ และเอกสารขั้นตอนประจำแพตช์ของโครงการที่มีอยู่ เทียบกับซอร์สจริงเมื่อข้อมูลรุ่น/branch ขัดกัน ฐานงานนี้คือเกม Company ปัจจุบันบน main ไม่ใช่การย้าย JS2 เข้าเกม
- ห้ามแก้ human-core.js, CORE_LOCK.json, สูตรแกนบุคลิก/ค่านิยม/ความถนัด/สถานะ หรือหลบตัวตรวจล็อก เพิ่มระบบธุรกิจภายนอกแกนได้
- ผู้เล่นเป็นผู้สังเกตการณ์ NPC ทำงานบริหารเอง ห้ามแก้ปัญหาด้วยการให้ผู้เล่นกดเปิดใบงาน รับออเดอร์ หรือซื้อรถแทน CEO
- simulation เป็นเจ้าของเวลา RNG เงิน ทรัพยากร และผลตัดสินใจ UI อ่าน snapshot และส่งคำสั่งผ่าน API
- เงินเป็นสตางค์จำนวนเต็ม ลงบัญชีครั้งเดียว แยกเงินบริษัทกับ wallet ส่วนตัว ห้ามสร้างรายได้/ความรู้/วัตถุดิบฟรีเพื่อทำให้เทสต์ผ่าน
- งานค้างของผู้อื่นต้องรักษาไว้ ไม่ force push หรือแก้ประวัติทับ

## ลำดับลงมือที่แนะนำ ให้คุณปรับได้
A. ทำ coverage matrix ของทุก product, material, app, service, fleet และ asset ในฐานจริง: แหล่งความต้องการ → เสนอทางเลือก → ตรวจความพร้อม → อนุมัติ → จัดหา/วิจัย/ลงทุน → ทำงาน → QC → ส่งมอบ → บัญชี/รับเงิน → ซ่อม/สนับสนุน → ทบทวน
B. แก้จุดเชื่อมที่ขาดก่อนขยายรายการ บท 31 เป็นประเด็นที่พบจากฐานเก่าให้ตรวจยืนยัน ไม่ถือว่าเป็นบั๊กที่พิสูจน์ครบทุกกรณี
C. ออกแบบ product family และ capability graph ที่ใช้ร่วมกัน แต่แต่ละธุรกิจยังมีขั้นตอนเฉพาะจริง
D. ขยายจากบท 28/30 และคิดเองเพิ่ม ใช้รายการเดิมซ้ำเมื่อเทียบเท่า แยกเมื่อคุณสมบัติทางกายภาพ/มาตรฐานต่างจริง กำหนดจำนวนตามคุณภาพและเวลาที่ทำได้ พร้อมรายการ deferred ที่ชัด ไม่อ้างว่า 96 ข้อเสนอถูกพัฒนาทั้งหมดหากยังไม่ได้ทำ
E. เชื่อม CEO/บอร์ดกับแผนลงทุนและแผนจัดหาความสามารถ ให้บุคลิกมีผลต่อการเลือก ไม่ใช่ใช้เป็นคำอธิบายกลบเส้นทางที่ไม่เคยถูกเรียก
F. ทดสอบสถานการณ์อัตโนมัติจริงและการอนุรักษ์เงิน/วัตถุดิบ/กำลังคน แล้ว build และทดสอบเบราว์เซอร์

## ข้อกำหนดต้นน้ำที่ย้ำเป็นพิเศษ
แร่ในแหล่งธรรมชาติ น้ำดิบ อากาศ และพลังงานธรรมชาติเป็นแหล่งกำเนิดที่ต้องมีข้อจำกัดการเข้าถึง/การเก็บเกี่ยว น้ำตาล แป้ง กระดาษ ดีเซล แนฟทา เหล็ก ปุ๋ย และชิปไม่ใช่ต้นน้ำธรรมชาติ ข้าว พืชผล นม น้ำยาง และไม้จากป่าปลูกเป็นผลผลิตชีวภาพ ต้องมีวงจรผลิต ไม่ใช่เสกจากที่ดิน
เมล็ดพันธุ์/ต้นกล้าต้องมาจากการซื้อหรือขยายพันธุ์ที่หักต้นทางจริง พืชที่เก็บพันธุ์เองได้ควรทำได้ตามชีววิทยา ไม่บังคับว่าพืชทุกชนิดต้องใช้เมล็ด: อ้อยใช้ท่อนพันธุ์ ปาล์ม/ไม้ใช้กล้า ข้าวใช้เมล็ดที่ยังงอกได้ ห้ามปลูกด้วยข้าวสารหรือแป้ง
แยก biological class จากระดับแปรรูป ตรวจวัตถุดิบชื่อรวมเดิมที่มีความหมายขัดกัน เช่น soy/นม, สมุนไพร/ถั่วเหลือง, crude oil/แนฟทา และแร่หลายชนิด ไม่ทำสูตรที่สร้างธาตุจากวัตถุดิบที่ไม่มีธาตุนั้น

## เกณฑ์สำเร็จและสิ่งส่งมอบ
- แต่ละรายการที่ทำจริงมี ID บทบาท ขั้นตอน อินพุต/เอาต์พุต เทคโนโลยี คน อาคาร เงินทุน ตลาด และเหตุผลที่ NPC จะเลือก/ไม่เลือก
- ทุกธุรกิจ/ผลิตภัณฑ์ที่เปิดใช้งานได้ มีอย่างน้อยหนึ่งสถานการณ์สมเหตุสมผลที่ NPC เข้าถึงและทำสำเร็จโดยไม่เรียกคำสั่งบริหาร/เสกเงิน/เสกเทคโนโลยีจากเทสต์เพื่อข้ามกระบวนการ การกำหนดทุนตั้งต้นแบบมีบัญชีใน fixture ทำได้ แต่เทสต์ต้องผ่านเส้นทางตัดสินใจจริง
- มีเทสต์กรณีขาดเทค ขาดเงินทุนหมุนเวียน ขาดคน/เครื่องมือ/วัตถุดิบ ตลาดไม่คุ้ม และกรณีเลือกเก็บเงินอย่างมีเหตุผล
- ส่ง coverage matrix ผลก่อน/หลัง เหตุผลการตัดสินใจ และผลตรวจจริง ไม่ถือว่าเทสต์เก่าผ่านเท่ากับระบบใหม่ครบ
- รัน npm test, npm run check, npm run build, npm run test:browser รวม benchmark ที่กฎโครงการกำหนด แจ้งข้อจำกัดจริง
- อัปเดตเอกสารสถานะ/รายงานแพตช์/API และไฟล์เล่นเดี่ยวจาก source แพ็ก ZIP เกมที่สมบูรณ์ตามขั้นตอนเดิม โดยไม่ใส่ .git, node_modules, cache, ZIP ซ้อน หรือเกมอื่น

เริ่มจากตรวจโครงการ แล้ววางแผนและลงมือพัฒนาให้เสร็จตามขอบเขตที่คุณประเมินสมเหตุสมผล ใช้ดุลยพินิจของคุณและเพิ่มไอเดียของคุณเอง พร้อมอธิบายการเลือกในรายงานแพตช์
