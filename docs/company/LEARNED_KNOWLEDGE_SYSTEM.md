# วิชา NPC เทคโนโลยีบริษัท และความพร้อมธุรกิจ

ฐานการเปลี่ยนแปลง: main `359bace`, เกม v2.2.0 → v2.3.0 ผู้เล่นรายงานการซูมไม่ได้ ภาพบริษัทกระจัดกระจาย และแต้ม R&D ปลดล็อกทุกอุตสาหกรรมเร็วเกินไป

## ขอบเขตข้อมูล

- `p.profile` และ `p.state`: มนุษย์ตาม Human Core เดิมที่ล็อก ไม่แก้ไฟล์สูตร
- `p.skills`: ทักษะงานเดิมที่ core ประเมิน; `p.education.subjects`: วิชาที่เรียนรู้เพิ่ม 170 วิชา แยกจาก core
- `practiceMinutes`: เวลาศึกษา/ฝึก; `appliedMinutes`: ลงมือทำงานจริง; `course`/`courseLevel`: หลักสูตรที่กำลังเรียน
- `w.knowledge.projects`: กระบวนการเฉพาะสินค้า/วัตถุดิบ มีวิชาที่ต้องใช้ งบที่จ่าย ชั่วโมงงานแต่ละวิชา วัตถุดิบต้นแบบ ระยะวัน ผลตรวจรับ และผู้ร่วม
- `w.research.points`: เก็บเพื่ออ่านข้อมูลเก่า/คำสั่ง sandbox เดิมเท่านั้น ไม่ใช้ปลดล็อกสินค้าและกระบวนการ

## จากความถนัดสู่ความเชี่ยวชาญ

วิชาแต่ละอันอ้าง `subjectSpec`: ชื่อ หมวด วิชาก่อนหน้า ระดับที่ต้องมี แบบจำลอง aptitude หลายแกน และผลต่องาน น้ำหนักรวม 1.0; ตารางครบอยู่ใน [ทะเบียน](KNOWLEDGE_SUBJECT_CATALOG.md)

`subjectTalent` เป็นค่าเฉลี่ยถ่วงน้ำหนักจาก aptitudes ปัจจุบัน; `subjectPotential` อ่าน potential ของแกนเดียวกัน; เพดานความรู้ = min(100, 75 + 0.25 × potential ถ่วงน้ำหนัก) ไม่แทนความรู้เริ่มต้น

อัตราฐานต่อชั่วโมง: ต่ำกว่า 40 = .25, 40–59 = .14, 60–79 = .06, 80–94 = .025, 95 ขึ้นไป = .008 แล้วคูณ learningSpeed, talent, สภาพพลังงาน/เครียด และ conscientiousness; งานจริงใช้ .35 ของอัตราเรียน พร้อมสะสม appliedMinutes ต้องมีงานจริง 40 ชั่วโมงก่อนเกิน 80 และ 200 ชั่วโมงก่อนเกิน 95 การปรับความถนัดลงไม่ลบความรู้เดิม

ระดับ: 20 พื้นฐาน, 40 ปฏิบัติงานได้, 60 ขั้นสูง, 80 ผู้เชี่ยวชาญ, 95 เชี่ยวชาญสูง เป็นสเกลเกม ไม่ใช่การรับรองคุณวุฒิตามกฎหมาย คณิตศาสตร์ประยุกต์ต้องมีพื้นฐาน 40 และคณิตศาสตร์ขั้นสูงต้องมีประยุกต์ 60

`subjectPerformance` ผสมความรู้ .65 + talent .20 + ประสบการณ์ลงมือ .15 แล้วลดตามความเหนื่อย/เครียด ทักษะ/สภาวะจาก H.evaluateAbility ยังทำงานตามเดิม learned subject เพิ่มตัวคูณเวลา .8 + score × .004 และคุณภาพ (score−50) × .001 ในงานผลิต/QC/วิจัย/สำนักงาน/ขนส่งที่มีการผูก subject ผ่าน `jobSubject` วิชาเสริมอื่นส่งผลผ่าน gate หลายวิชาและชั่วโมง/คุณภาพงานแต่ละแขนงของโครงการ ไม่ใช่ทุกวิชาคูณความเร็วทุกงาน

## R&D และการลงทุน

1. ผู้บริหารเลือกโครงการจากช่องว่างความรู้ทีม ตลาด ส่วนต่างต้นทุน เงินสำรอง ความเสี่ยง และทางเลือกซื้อภายนอก; บริษัทที่เน้นถือครองห่วงโซ่อาจศึกษา recipe ที่ซื้อซ้ำมาก
2. โครงการใหม่ใช้ 21–56 วันเป็นอย่างน้อยและ 100–300 ชั่วโมงตามความซับซ้อน กระจายเวลางานให้แต่ละวิชาที่ใช้ ไม่ได้แค่รอวันครบหรือมีพนักงานเก่งอยู่เฉย ๆ
3. ทีมต้องครอบคลุมวิชาที่กำหนด บุคลากรเรียนวิชาก่อนหน้าจากหลักสูตรที่มีค่าใช้จ่ายและเวลาทำงานจริง การเรียน/วิจัยมีเพดาน 8 ชั่วโมงต่อคนต่อวัน; การศึกษาไม่มีระบบผู้สอน NPC แบบจองตัวในรุ่นนี้ เป็นหลักสูตรภายนอกที่คิดค่าใช้จ่าย
4. ต้นแบบต้องเบิก BOM หรือ recipe inputs ที่มีจริงและยังไม่จอง งานจัดซื้อปกติจัดหา input ที่ขาด ชั่วโมงแต่ละแขนงและผู้ทำถูกบันทึก โครงการจ่ายค่างานทดลอง/การเรียนใน ledger `equipment` นอกเหนือจากค่าจ้างตามงานเดิม
5. ฝ่ายคุณภาพใช้เวลาตรวจอย่างน้อย 4 ชั่วโมง เป็นคนละคนกับผู้ทำต้นแบบ ผลตรวจมีโอกาสไม่ผ่านตามคุณภาพการทดลองและผู้ตรวจ ส่งกลับแก้ 20% และใช้ตัวอย่างใหม่ ไม่มี output ต้นแบบให้ขายเป็นรายได้
6. ผ่านแล้วจึงเป็นกระบวนการที่บริษัทรู้ แต่ readiness ยังต้องมีทีม วิชาร่วม เงินหมุนเวียนและเครื่องจักรพร้อม หากผู้รู้คนเดียวลาออก สถานะผ่านของเอกสารยังอยู่แต่ไม่อนุญาตรับออเดอร์ใหม่ที่ทำไม่ได้

แบบจำลองยังใช้กลไกสถานที่/กำลังผลิตและค่าบริการเดิม ไม่ได้เพิ่มใบอนุญาตทางกฎหมายรายประเทศ มหาวิทยาลัยที่จำลองเต็มรูปแบบ หรือระบบ tutor booking จึงห้ามอ้างว่ามีสิ่งเหล่านั้น

## Gate และเส้นทางใช้งาน

- สินค้า 42 รายการ: `productRequirements`/`productReadiness`; สินค้าเริ่มต้นประกอบจาก kit มีเงื่อนไขช่าง/ความปลอดภัย/คุณภาพ/บัญชีพื้นฐาน ส่วนแบบใหม่ใช้วิชาของตระกูลร่วมและกระบวนการผ่านรับรอง
- กระบวนการวัตถุดิบที่เคยต้องใช้ research points: `materialRequirements`/`materialReady`/`craftMaterialRecipe`/`runMidstreamRefining`; ผลิตไม่ได้ยังซื้อจากตลาดได้ สูตรพื้นฐานที่ไม่มี tech gate เดิมยังต้องมีวิชาของทีมและความปลอดภัยถึงเกณฑ์ ส่วนกระบวนการที่มี tech gate ต้องผ่านโครงการรับรองด้วย
- บริการ 10 แบบ: `SERVICE_SUBJECTS` และ `startServiceOrder` ตรวจทีมและวิชาหลักของผู้รับผิดชอบก่อนเปิดงาน; ชิ้นส่วน/ต้นทุน/ลูกค้า/การจองตัวตามระบบเดิม
- ซอฟต์แวร์: ต้องมีพื้นฐานซอฟต์แวร์ การเขียนโปรแกรม วิเคราะห์ความต้องการ ทดสอบ และจัดการรุ่น ผู้ลงมือเขียนต้องมี programming/software ถึงเกณฑ์เอง; โต๊ะและความว่างตามระบบเดิม
- เกษตร: ปลูกต้องมีเกษตร ดิน พันธุ์ และน้ำ; เก็บเกี่ยวต้องมีวิชาจัดการผลผลิต; การดูแลปศุสัตว์ต้องมีการเลี้ยง สุขภาพ และอาหารปลอดภัย กองรถตรวจวิชาวางเส้นทาง ขับรถ และความปลอดภัยสินค้า; ผู้ขับต้องรู้การขับถึงเกณฑ์เอง

## ซื้อเทคโนโลยีและความรู้ส่วนบุคคล

`acquireTechnologyLicense` ซื้อเทคโนโลยีเฉพาะเป้าหมายในราคา 3 เท่าของฐานค่างานวิจัย (ไม่รวมค่าจ้าง/ต้นแบบ) จ่ายจริงใน ledger แต่ยังต้องมีทีมครบวิชา ใช้ 40% ของชั่วโมงโครงการเดิม และ 10–25 วันในการรับถ่ายทอด/ทดสอบ ตรวจคุณภาพอิสระและ input เหมือนวิจัยเอง NPC ที่รับความเสี่ยงมากและมีเงินสำรองสูงอาจเลือกซื้อ แทนการวิจัยเอง สินค้าขั้นกลางยังซื้อได้เมื่อไม่ต้องการสร้างโรงงานต้นน้ำ

ทุกวิชาเรียนได้โดยไม่ดูประเภทธุรกิจของนายจ้าง ความรู้ที่ยังไม่มีงานใช้ไม่ได้ถูกล็อก พนักงานมีประวัติวิชาเฉพาะงานและความสนใจส่วนตัวหลากหลาย ตั้งต้นด้วย seed เดียวกันจะได้ประวัติเดิม ผู้ที่พร้อมและมีแรงจูงใจอาจศึกษานอกงานช่วง 20:00–21:00 จ่ายจากกระเป๋าตัวเองและเสียเวลาพัก ใช้ H.tickState แบบเรียนรู้ ไม่หักเงินบริษัท และยังข้ามวิชาพื้นฐานหรือข้อกำหนดประสบการณ์ไม่ได้

## UI, เซฟ และ API

หน้าบริษัทมีภาพรวม องค์ความรู้/R&D สารบัญวิชา ธุรกิจ/สินค้า บอร์ด/แผน โครงสร้าง/คน และทรัพย์สิน/ทรัพยากร แสดงผู้รู้รายวิชาและช่องว่างของทีม ชื่อวิชาเป็นภาษาไทย Edit Hub มีการแก้วิชารายคน 0–100 พร้อม event โดยไม่เปลี่ยนแกนมนุษย์

หน้าตัวละครเพิ่มแท็บ **ความรู้** แสดงชื่อวิชา Lv1–Lv5 ระดับย่อย ชั่วโมงฝึก/งานจริง ความสนใจและการเรียนของบุคคล; ระดับความรู้ไม่ใช่เลเวลตำแหน่งงาน

snapshot: `companyKnowledge`, `catalog.products[].readiness`, `people[].education`; sim command `beginKnowledgeProject` มี targetId/kind; คำสั่ง `acquireTechnologyLicense` ใช้ targetId/kind เดียวกัน; `directorEdit/setSubject` ใช้ personId/subjectId/level

เซฟเก่าที่รองรับและไม่มี knowledge ถูกย้ายผ่าน `ensureKnowledge` เก็บรายการปลดล็อกเก่าไว้ `historicalBlueprints`, เก็บเงิน คน สต็อก และออเดอร์เดิม; ถอนสิทธิเปิดสินค้าใหม่จากแต้มรวมและล้างงานวิจัยแบบเก่าที่ไม่มีเป้าหมาย ไม่สัญญาว่าออเดอร์เดิมจะผลิตต่อได้โดยไม่มีผู้รู้ การพัฒนาต่อใช้สถานะจริงของทีม ข้อมูลวิชา/โครงการผิดรูปถูกปฏิเสธก่อนแทนโลกปัจจุบัน
